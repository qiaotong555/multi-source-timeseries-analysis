### 详细卡片（只有需要边界的才展开）

**A1　Windows 静默 traceback**

- 现象：`src/mtsa/timeout_guard.py:92` 用 `subprocess.run(..., text=True)` 未指定 `encoding`，
  子进程输出中文、控制台为 GBK 时读线程解码失败。2026-10-25 在 stock 与 agent 两次运行中复现。
- 根因（实测定位，比"子进程输出中文"更具体）：触发物是 statsmodels 的 `InterpolationWarning`
  （`stats_tests.py:141` 的 KPSS）。告警首行是源码绝对路径，路径含中文用户名
  `C:\Users\乔佟\...`；子进程按 locale（cp936）写 stderr，父进程在 `-X utf8` 下按 UTF-8 读，
  第 9 个字节正好是「乔」的首字节 `0xc7`（`C:\Users\` 共 9 字节）。崩溃发生在读管道的
  子线程，所以主流程照常成功、只在 stderr 留下半截 traceback——比彻底失败更难排查。
- 改法：`encoding="utf-8", errors="replace"`，并在子进程 env 里补 `PYTHONIOENCODING=utf-8`。
- 边界：只改解码，不改超时语义、不改失败分类。
- 已完成（2026-10-25）：
  - 证据一：pipeline（17.7 s）/ stock（7.7 s）/ weather-agent（14.4 s）三次实跑均 rc=0、
    stderr **0 字节**，无 `UnicodeDecodeError`。
  - 证据二：`tests/test_timeout_guard.py::test_child_stdio_is_forced_to_utf8` 锁住
    `encoding` / `errors` / `PYTHONIOENCODING` 三个契约点；旧实现缺 `encoding` 参数，该用例必失败。
- 遗留（不在 A1 范围，需单列）：子进程 stderr 在成功路径上被整体丢弃，因此这类
  KPSS 数值告警现在是**静默**的。要可见，需把非空 stderr 并入 `result.warnings`——
  那是产品语义变更（报告要多一类告警），不能混在这次解码修复里做。

**B2　校验失败后重跑**

## F 预测分析（已交付，2026-10-24）

交付摘要：

| 项 | 结果 |
| --- | --- |
| 范围 | 仅天气、单变量、默认关闭（`--forecast`）；股票不做 |
| 方法 | seasonal_naive（基线）/ moving_average / drift；候选须比基线低 5% 才替换 |
| 回测 | 最后 30% 内 40 个 origin，严格只用 t 及以前的数据 |
| 区间 | 90%；滚动窗口 + 尺度归一池化；覆盖率只用最后 40% 的 origin |
| 覆盖 | 11 份数据 58 列，MASE≤1.0 占 0.741，汇总覆盖率 0.8673 |
| 兼容 | 关闭时不写 `data.forecast`，`data` 其余字段逐位不变 |

立项时草案的 3 处偏离（都写进记录，不放宽标准）：
1. 草案写「单/多变量」，实际只做单变量——多变量需要外部变量与特征工程，不在本轮范围；
2. 草案 F2 写「覆盖率 0.85–0.95」，正式任务书改为 [0.80, 0.98]——覆盖率由 384 个回测点
   估计，Wilson 95% 半宽约 ±0.03，58 列逐列用 0.85–0.95 会把抽样噪声判成方法缺陷；
3. 草案「打乱未来特征后指标不得变好」改成更强的「改未来段后预测逐元素不变」——
   本项目预测没有外部特征，前者的检验对象不存在。

## 成本语义补强（2026-10-25，用户拍板）

三项决定与落地：

1. **价目表手填**：随包 `prices/` 四份（deepseek-flash / deepseek-v4-pro × peak / off_peak），

3. **金额预算「跑完再标记」**：`--max-cost`（或 `MTSA_MAX_COST`）超支不中止，
   只写 `cost.budget.exceeded` + warnings + 报告里那一行；`status` 仍为 `succeeded`。
   与之相对的 `--agent-max-tokens` 仍是下一次调用前硬停——两套语义并存，边界写在
   `doc/接口与字段.md`「成本语义（E2）」。

偏差且无人察觉。新增可选 `model` 字段，不一致时标 `model_match=false` 并进 warnings。

验证：`tests/test_cost_budget.py` 10 项（随包四表的数字与供应商页逐项比对、预算只标记
不中止、模型不一致告警、无价目表时预算前置失败、pipeline 下预算不适用）。
