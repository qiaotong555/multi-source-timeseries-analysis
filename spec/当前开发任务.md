## T1.4 性能与规模基准

| 项目 | 内容 |
| --- | --- |
| 任务编号 | T1.4（可观测性补强） |
| 状态 | **已完成**（2026-10-20） |
| 依赖 | 无（独立维度） |

### 1. 目标

此前分析耗时与内存占用从未测量。本任务建立三档规模基准（1e4 / 1e5 / 1e6 行），给出各节点耗时分解、峰值内存与规模效应，并把 1e5 档的两个数字纳入验收指标。

### 2. 接口

- `evals.benchmark.benchmark(scales)`：跑基准并写 `evals/benchmark_results.json`。
- `evals.benchmark.build_frame(n_rows, stations)`：构造同结构合成数据。
- `evals.run_evals._load_benchmark()`：读取缓存；缺失时指标记 9999 而非 0。

### 3. 边界

- 不改动任何数据集，基准数据在临时目录生成并销毁。
- 1e6 行不作为验收项（非本课题场景），但超时事实必须记录。
- 不为提高分数而放宽阈值。

### 4. 验收标准

| 序号 | 标准 | 实测 | 结论 |
| --- | --- | --- | --- |
| 1 | 三档规模可测，子进程隔离且超时可终止 | 1e6 超时被正确捕获 | 达成 |
| 2 | 计时与内存分轮，互不污染 | 两轮结果独立 | 达成 |
| 3 | 1e5 行分析耗时 ≤ 120 s | 68.93 s | 达成 |
| 4 | 1e5 行峰值内存 ≤ 1024 MB | 849.0 MB | 达成 |
| 5 | 瓶颈可定位到节点 | `stat_tests` 占 90.4% | 达成 |
| 6 | 指标与测试全通过 | 21 项指标、109 项测试 | 达成 |

### 5. 遗留问题

`stat_tests` 单点占 90.4% 且超线性（行数 10 倍 → 耗时 50 倍），源于 ADF/KPSS 的 `nlags="auto"` 随样本量扩大搜索范围。优化方向：固定最大滞后阶、对长序列降采样后检验、或改用更轻的平稳性判据——未在本轮进行，属检测器性能改造。1e6 行无前置规模检查，也待补。详见 `doc/改进记录.md` 改进 #4。

## T1.3 变化点扫描：位置 × 幅度网格标定

| 项目 | 内容 |
| --- | --- |
| 任务编号 | T1.3（验证体系补强，变化点灵敏度标定） |
| 状态 | **已完成**（2026-10-20） |
| 依赖 | T1.1 |

### 1. 目标

原变化点验证只用一处注入（+18 hPa、第 12000 点），无法区分「算法准」与「这一处恰好容易」，也给不出「多小能检出」。改为 5 个位置 × 8 个幅度（含 0 基线）的网格扫描，产出检出率曲线、定位误差分布与伪报率。

### 2. 接口

- `evals.changepoint_scan.scan_change_points(clean, plan, column, positions, deltas, tolerance, sse_ratio)`：网格注入并汇总。
- `evals.changepoint_scan.format_grid(result)`：渲染为位置 × 幅度矩阵。
- 判据参数：`plan.parameters["change_point_sse_ratio"]`，默认 0.7（行为不变）。

### 3. 边界

- 不改动任何数据集文件，注入仅在内存中进行。
- 不调整判据阈值——本轮只做标定，不为了让曲线好看而放宽或收紧。

### 4. 验收标准

| 序号 | 标准 | 实测 | 结论 |
| --- | --- | --- | --- |
| 1 | 网格覆盖 5 个位置 × 8 个幅度（含 0 基线） | 40 格 | 达成 |
| 2 | Δ=18 时五个位置全部检出 | 检出率 1.00 | 达成 |
| 3 | 命中格子的定位误差 90 分位 ≤ 3 | 0 | 达成 |
| 4 | 0 幅度伪报率 ≤ 0.20 | 0.00 | 达成 |
| 5 | 判据可参数化，默认行为不变 | `change_point_sse_ratio` 默认 0.7 | 达成 |
| 6 | 指标与测试全通过 | 19 项指标、103 项测试 | 达成 |

### 5. 遗留问题

检出下限 18 hPa，约为该列残差噪声标准差（2.28）的 7.9 倍，低于此幅度的跳变会漏检；该下限随噪声尺度变化，不可跨数据集套用。判据仍是单一全局比例，导致末段难度显著高于前段——换上 BIC 或 Pettitt 检验可让判据随样本量自适应，属检测器改造，未在本轮进行。详见 `doc/改进记录.md` 改进 #3。

## T1.2 异常题型扩展与事件级评估

| 项目 | 内容 |
| --- | --- |
| 任务编号 | T1.2（T1.1 的延续，验证体系补强） |
| 状态 | **已完成**（2026-10-20） |
| 依赖 | T1.1 |

### 1. 目标

评估集原先只覆盖孤立点跳变，不覆盖持续段异常；且判定粒度为点级，一段持续异常会被判成多个误报。本任务要求：评估集同时覆盖两类异常，判定粒度扩展到事件级，并按类型分别报告召回。

### 2. 接口

- `fixtures/gen_fixtures.py::gen_weather_eval`：注入两类异常，标签增加 `anomaly_type`、`event_id`。
- `evals.split_eval.event_pr(anomalies, labels, max_gap_seconds)`：事件级 P/R 与分类型召回。
- 新增指标：事件级异常召回率、集体异常召回率、dev 与 holdout 召回退化。

### 3. 边界

- 不改动演示集 `weather_v1`。
- **不实现段级检测器**：本轮只扩展评估覆盖面，不扩展检测能力（原因见改进记录 #2 第 4 节）。

### 4. 验收标准

| 序号 | 标准 | 实测 | 结论 |
| --- | --- | --- | --- |
| 1 | 评估集同时含孤立点与持续段 | 60 点 + 24 段（252 点 / 84 事件） | 达成 |
| 2 | 持续段每段 ≥ 5 个点，段长显著小于趋势窗口 | 每段 8 点，窗口 24 | 达成 |
| 3 | 事件级比对能合并连续检出 | 6 项专项测试通过 | 达成 |
| 4 | 按类型分别报告召回 | point 0.833 / collective 0.917 | 达成 |
| 5 | 指标全部通过 | 17 项全通过 | 达成 |
| 6 | 演示集哈希不变 | `586044da…` | 达成 |

### 5. 遗留问题

检测器仍为逐点判定，对「单点不超阈、整段持续偏移」的漂移型异常无能为力。根因是残差噪声 AR(1) 系数 0.97，24 小时窗口的有效独立样本量不足 1，滑动均值检验无统计功效。详见 `doc/改进记录.md` 改进 #2 第 4 节。

## T1.1 评估集划分与阈值独立性验证

| 项目 | 内容 |
| --- | --- |
| 任务编号 | T1.1（T1 的补强项，不新增能力） |
| 状态 | **已完成**（2026-10-20） |
| 起始日期 | 2026-10-20 |
| 依赖 | T1 |

### 1. 目标

消除 T1 评估中的自证问题：异常检测阈值原先在唯一一套带标签数据上选定、又在同一套数据上报告指标。本任务要求**参数只在 dev 上选、结论只在 holdout 上报**。

### 2. 输入与输出

- 输入：`fixtures/weather_v1.csv`、`fixtures/labels_weather_v1.csv`。
- 输出：`evals/eval_results.json` 中的 `_split_eval` 段与控制台划分表；每折的 dev/holdout 数据切片落在 `artifacts/eval_split/<fold>/`。

### 3. 接口

- `evals.split_eval.split_by_time(frame, time_column, start_ratio, end_ratio)`：按唯一时间点切分。
- `evals.split_eval.select_threshold(scan, min_precision)`：只依据 dev 扫描结果选阈值。
- `evals.split_eval.run_split_eval(...)`：三折前向滚动，返回 `{folds, summary}`。
- `AnalysisRequest.param_overrides`：新增字段，用于在不改代码常量的前提下覆盖计划参数；CLI 对应 `--param KEY=VALUE`。

### 4. 边界

- 不改动 `weather_v1` 与 `stock_v1` 的内容与哈希。
- 不做随机切分，不做跨场景参数迁移。
- 不因「想通过」而放宽判定标准。

### 5. 错误行为

- `param_overrides` 出现计划中不存在的键：中止并返回 `invalid_param_override`，附 `unknown` 与 `allowed` 列表。
- 单折运行失败：该折记 `status=failed`，不参与汇总。
- 有效折数不足：整体判 `inconclusive`，不判通过。

### 6. 验收标准

| 序号 | 标准 | 实测 | 结论 |
| --- | --- | --- | --- |
| 1 | 切分按时间、不重叠、并集完整、同刻记录不劈开 | 22 项专项测试通过 | 达成 |
| 2 | 阈值只由 dev 段决定，选择规则固定 | 三折分别选出 8.0 / 7.0 / 7.0，不再落在网格边界 | 达成 |
| 3 | holdout 端到端重跑，不用 dev 结果顶替 | 每折 `run_analysis` 独立运行 | 达成 |
| 4 | 有效折数 ≥ 2 才判通过 | 3 / 3 | 达成 |
| 5 | 指标给出不确定性度量 | 已输出 Wilson 95% 下界 | 达成 |
| 6 | 每折 holdout 真值 ≥ 10 | 12 / 12 / 12 | 达成 |
| 7 | 演示集哈希不变 | `586044da…` 与 T1 一致 | 达成 |

### 7. 遗留问题

评估集 `weather_eval_v1` 把每折 holdout 真值提到 12 个后，判定由「不可判定」转为通过，指标为 holdout 精确率 1.000、召回率 0.722。但 12 个样本下召回率的 Wilson 95% 下界仅 0.391 至 0.552，**点估计达标而统计上无法排除真实召回低于 0.70**。引用该指标须同时给出下界；若要收窄区间需把每折真值提到 30 个以上（总量约 150），当前未做。详见 `evals/评估记录.md` 第 3 轮。

## T1 通用时序分析引擎核心链路与两个场景适配器

| 项目 | 内容 |
| --- | --- |
| 任务编号 | T1 |
| `task_id` | `multi_source_timeseries_analysis` |
| 状态 | **已完成并归档**（2026-09-29） |
| 起始日期 | 2026-09-27 |
| 依赖 | 无（首个任务） |

> T1 已达成下列 7 条验收标准并归档，完成情况见 `spec/已完成任务.md` 与 `evals/评估记录.md`。
> 下一项任务 T2（对外 REST 服务与异步任务）见 `spec/未来规划.md`，启动前需把该文档内容
> 提升为新的「当前开发任务」。下面的内容保留为 T1 的历史规格，用于追溯验收口径。

### 1. 目标

建立与场景解耦的通用时序分析引擎，并用**两个场景适配器**证明同一工作流可迁移：

- 主场景 `weather`：完成完整分析链路。
- 扩展场景 `stock`：复用同一引擎完成迁移验证，并额外执行 walk-forward 回测与未来数据泄漏检查。

引擎必须覆盖规范 4.7 的核心任务：识别时间轴和变量角色；检查缺失、重复、乱序、异常值和采样不连续；执行重采样、插值、标准化、滤波或去趋势；根据问题选择趋势、波动、相关性、频谱、变化点、异常分析；生成图表并用代码复算关键结论。

### 2. 输入

```text
输入数据集路径（CSV/Excel/Parquet/NPY/MAT/HDF5）
时间字段、数值字段、分组字段（可缺省，由 profiler 推断）
单位、采样率或采样间隔（可缺省，由 profiler 推断）
数据说明（自然语言）
分析问题（自然语言）
场景标识 scene_id：weather | stock（可缺省，由自动识别给出并需确认）
随机种子 seed（默认 20260927）
```

输入文件以**只读**方式打开，任何情况下不修改、不移动、不删除。

### 3. 输出

结构化 `AnalysisResult`（Pydantic 校验后落盘为 `artifacts/<run_id>/result.json`）：

```text
data       : 清洗后数据表、特征表、量化指标表（metrics）
evidence   : 每条结论对应的 metric_id / artifact_id / 计算代码位置
datasets   : 输入数据集版本（路径、行数、列、哈希、时间范围）
artifacts  : 静态图 PNG、交互图 HTML、清洗后数据 CSV、可复现脚本、报告 Markdown/HTML
warnings   : 数据质量与口径告警（缺失率、采样不连续、单位变化等）
events     : 节点执行轨迹（节点名、耗时、输入摘要、输出摘要）
error      : 失败时的 code/message/details
```

以及 `report.md`：数据质量报告、分析计划、清洗后数据说明、特征表、量化指标表、图表清单、异常点与变化点清单、统计检验结果、结论与限制说明。

### 4. 接口（本任务内部契约，对外 REST 不在本任务范围）

| 函数 | 签名 | 说明 |
| --- | --- | --- |
| `load_dataset` | `(path: str, spec: DatasetSpec) -> RawDataset` | 多格式导入 |
| `profile_dataset` | `(raw: RawDataset) -> DatasetProfile` | 字段与采样摘要、时间轴与变量角色识别 |
| `check_quality` | `(raw, profile) -> QualityReport` | 五类问题检查 |
| `clean_series` | `(raw, profile, plan) -> CleanDataset` | 重采样、插值、标准化、滤波、去趋势 |
| `compute_metrics` | `(clean, plan) -> MetricTable` | 时域量化指标 |
| `analyze_spectrum` | `(clean, plan) -> SpectrumResult` | FFT/功率谱/时频 |
| `run_stat_tests` | `(clean, plan) -> TestResultTable` | 平稳性、自相关、正态性、趋势检验 |
| `detect_anomalies` | `(clean, plan) -> AnomalyResult` | 异常点与变化点 |
| `build_figures` | `(all results, plan) -> list[Artifact]` | 静态图与交互图 |
| `render_report` | `(all results, artifacts) -> Artifact` | 报告生成与结论绑定 |

场景适配器统一实现 `ScenarioAdapter`：`detect(df, profile) -> float`（置信度）、`plan(question, profile) -> AnalysisPlan`、`extra_metrics(...)`、`figure_specs()`、`conclusions(...)`。

### 5. 边界（不做范围）

- 不修改原始输入文件。
- 股票场景不提供真实投资建议、不做自动交易；回测不含交易成本与滑点，必须在结论中声明。
- 不预测彩票中奖号码（彩票场景不在本任务范围）。
- 不做跨数据集的自动联网检索。
- 不使用 LLM 参与任何数值计算；本任务不启用 LLM 节点。
- 不实现对外 REST 服务（见未来规划 T2）。

### 6. 错误行为

| 场景 | 行为 |
| --- | --- |
| 文件不存在或格式不支持 | `error.code = DATA_LOAD_FAILED`，列出支持的扩展名 |
| 未识别到时间字段 | `error.code = TIME_AXIS_NOT_FOUND`，返回候选列与其可解析比例 |
| 时间列不可解析比例 > 20% | `warning` 且在 `plan` 中标记降级；不静默丢弃 |
| 数值列全为缺失 | `error.code = EMPTY_NUMERIC_COLUMN` |
| 场景无法识别（最高置信度 < 0.34） | `error.code = SCENE_NOT_DETECTED`，要求显式指定 `scene_id` |
| 采样率低于分析所需（如日频数据请求日内分析） | `warning` + 在报告中声明不可执行项，不编造结果 |
| 回测检测到未来数据泄漏 | `error.code = LOOKAHEAD_VIOLATION`，回测结果不输出 |

禁止静默兜底：命中上述任一错误即中止对应节点并返回 `status=failed`，不返回占位结果。

### 7. 验收方式

1. `python -m pytest tests -q` 全部通过，覆盖正常、边界、失败、安全四类场景。
2. `python -m mtsa.cli run --scene weather --input fixtures/weather_sample.csv` 与 `--scene stock` 均能产出完整 artifacts。
3. 关键指标复算误差：对同一 fixture 用独立脚本复算收益率、波动率、最大回撤、相关系数、FFT 主频，相对误差 ≤ 1e-6。
4. 异常检测在带真值标签的 fixture 上 Precision ≥ 0.70、Recall ≥ 0.70。
5. 同输入重复运行一致率 100%（`result.json` 除 `run_id`、`generated_at` 外逐字节一致）。
6. 股票场景的未来数据泄漏检查用例必须失败（即有泄漏时引擎报错）。
7. 报告中每条结论均可通过 `evidence` 定位到指标或图表；无证据结论数为 0。

### 8. 开发顺序

数据契约与导入 → 摘要与质量 → 预处理 → 指标/频域/检验/异常 → 场景适配器 → 图表与报告 → fixture 与编排 → 测试与评估。
