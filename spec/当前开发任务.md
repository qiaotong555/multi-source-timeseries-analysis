## 方案 1：鲁棒性矩阵（立项 2026-10-23，已完成）

### 目标

补上「干净 fixture 之外的输入」这一证据缺口：脏数据、怪 schema、极端样本、越界问题时，
系统必须**要么明确拒绝，要么成功但显式声明降级**，不能崩溃，也不能静默给结论。

### 用例矩阵（先写后测）

| 组 | 用例 | 预期 |
| --- | --- | --- |
| 导入 | 文件不存在 / 0 字节 / 只有表头 / 畸形 CSV / 不支持格式 / 目录当文件 | `DATA_LOAD_FAILED` |
| 时间 | 无时间列 / 时间列不可解析 / 混合时区 / 时间戳全相同 / 乱序 / 重复 | 明确失败，或成功且 warning |
| 数值 | 无数值列 / 全 NaN 列 / 常数列 / inf / 1e12 量级 / 负降雨 | 明确失败，或成功且 warning |
| 规模 | 超上限（用小上限模拟）/ 恰好上限 / 1 行 / 10 行 | 超限 `DATASET_TOO_LARGE`；小样本明确失败或 warning |
| 编码 | GBK / BOM / 重复列名 | 成功，或明确失败 |
| 问题 | 空问题 / 超长问题 / 越界（预测未来）/ 注入 | CLI 空问题拒绝；其余成功且不得输出预测结论或泄漏提示词 |
| Agent 边界 | agent + 股票 / agent + 无模型 / agent + 坏输入 | `AGENT_SCENE_UNSUPPORTED` / `AGENT_UNAVAILABLE` / 前置错误码，且不调用模型 |

### 验收标准

| 编号 | 标准 | 验证方式 |
| --- | --- | --- |
| R1 | 不崩溃：每个用例都返回 `AnalysisResult`，且 `result.json` 落盘；未捕获异常即失败 | 矩阵逐例检查 + 顶层异常护栏 |
| R2 | 错误码可解释：失败用例的 `error.code` 在预期集合；成功用例必须有 `report.md` | 矩阵断言 |
| R3 | 不静默：降级数据成功时至少 1 条 warning；结论全部绑定证据（`no_evidence=0`） | 矩阵断言 |
| R4 | 越界不冒充：预测类问题不得输出「预测/forecast」结论 | 文本扫描 |
| R5 | 成本可控：小样本用例单例 < 30 s | 矩阵计时 |
| R6 | 全量回归通过（当前基线 36 文件 / 340 项） | `python run_tests.py --timeout 400` |

### 不做的事

- 不评估模型能力：矩阵固定 `MTSA_PLANNER=rule`，Agent 用例只测边界，不调用真实模型；
- 不修改任何检测阈值或结论判据；
- 不覆盖股票 Agent（用户明确暂缓）；
- 不把「1 行也能出完整报告」当成目标——小样本允许明确失败。

## 方案 2：独立标签与结论阈值标定（立项 2026-10-24，已完成）

### 目标

A 的结论级指标目前只能「只报告」：13 个用例共用 `weather_v1`，且没有冻结阈值。
本方案用一份**独立生成、独立标注**的数据，把结论级指标变成有阈值的门禁。
不使用多模型，也不在新数据上回调阈值。

### 独立数据

| 项 | 设定 |
| --- | --- |
| 文件 | `fixtures/weather_eval_v2.csv` |
| 生成器 | `fixtures/gen_weather_eval_v2.py`（seed=20261024，确定性） |
| 规模 | 365 天 × 小时 × 2 站点 = 17,520 行 |
| 信号 | 温度年振幅 10°C（峰值 7 月、谷值 1 月）+ 日周期 6°C + 线性趋势 +0.8°C/年 |
| 异常 | 36 个事件：24 个孤立点（6 列 × 4）+ 12 个持续段（6 列 × 2 段 × 8 小时） |
| 变化点 | 6 个均值跳变（气压 ≥20 hPa、温度 ≥4°C、湿度 ≥15%、风速 ≥3 m/s） |
| 缺失 | 8%（随机 + 1 个 12 小时连续缺口） |
| 标签 | `labels_weather_eval_v2.csv`：anomaly / level_shift_start / missing_gap_start |
| 真值 | `truth_weather_eval_v2.json`：温度趋势方向、年振幅、峰/谷月、日周期 |

> **固定版实际参数（2026-10-24，阈值未改）**：上表是立项初稿，固定时按实际系列数修正为
> **30 个异常事件 / 100 个异常点**（5 列 × 2 站点 × (2 孤立点 + 1 个 8 小时段)）、
> **2 个变化点**（`pressure@STA_A` day 60、`pressure@STA_B` day 200，均 +60 hPa）、
> 缺口标签为 `missing_gap_start`。修正原因见 `spec/项目承接已完成.md` 29.2。

### 用例与运行

4 个「全量分析」问题（措辞不同，均要求趋势/季节/异常/变化点），pipeline 与 agent 各 4 次：

```text
1. 分析温度的趋势、季节性和异常点，并检测变化点
2. 请全面检查这份天气数据的趋势、周期、异常与结构变化
3. 找出温度湿度的异常、气压的跳变，并说明季节规律
4. 做一次完整分析：趋势、季节性、异常点、变化点
```

Agent 固定 `deepseek-chat`、`guided`、`MTSA_PLANNER=rule`、`--agent-max-tokens 8000`。

### 阈值（先写后测，冻结）

阈值取自 A 的 pipeline 基线 + 领域下限的较严者，**在看到 v2 结果前冻结**；
若不过，如实记录，不放宽：

| 指标 | 阈值 |
| --- | --- |
| 异常事件 Recall | ≥ 0.80 |
| 异常事件 F1 | ≥ 0.40 |
| 变化点 F1 | ≥ 0.50 |
| 趋势正确率 | ≥ 0.80 |
| 季节正确率 | ≥ 0.80 |
| 结论证据覆盖 | = 1.00 |
| 成功率（每模式） | ≥ 0.90 |
| agent 非劣于 pipeline | 各已评分指标 ≥ pipeline − 0.10 |
| 趋势/季节已评分率（附加护栏） | ≥ 0.90 |

> 实际门禁共 24 项检查：上述 8 项 × 2 模式 + 2 项已评分率 × 2 模式 + 4 项非劣检查。

「未执行」按未覆盖真值计入，不能当作 0 分或通过。

### B2 标注协议（先写后测）

### B3 运行矩阵

10 份数据 × 4 个标准问题 × pipeline/agent = **80 次运行**。

四个标准问题：

1. 分析温度的趋势、季节性和异常点，并检测变化点；
2. 请检查这份数据的缺失、重复、乱序、采样缺口和单位变化；
3. 找出温度、湿度和气压的异常，并说明最显著的几个；
4. 做一次完整分析：趋势、季节性、异常点、变化点。

Agent 固定 `deepseek-chat`、`guided`、`MTSA_PLANNER=rule`、`--agent-max-tokens 8000`。
每份数据先跑 pipeline 确认可用，再跑 agent；失败也落盘并记录原因。

### B4 指标（逐数据集 + 宏平均 + 最差数据集）

不做「把所有行拼起来算一个总分」。每份数据单独计算：

- 成功率、证据覆盖率、结论需求覆盖率；
- 质量事件 Recall（L1）、异常 Precision/Recall/F1（仅 L2）；
- 变化点指标（仅 L2/有标注时）；
- Agent 工具覆盖率、未执行工具、token、终止原因。

汇总报告必须同时给出：**10 份逐数据集表、宏平均、最差数据集、失败清单**。
未标注事件不进入 FP/FN；未执行工具不能当作「没异常」。

## T2.13 token 预算（立项 2026-10-23，已完成）

> 验收记录见 `spec/项目承接已完成.md` 第 22 章。

### 目标

给 Agent 循环加一个**成本上限**：累计 token 达到上限时停止调用模型，并以明确的
终止原因结束。解决「长问题或反复试错时成本无上限，只能事后看账单」的问题。

### 背景

T2.8 起已记录 token（`data.agent.tokens`），但只记录不拦截。实测 13 用例平均
4,152 token/次，最大 7,854；步数上界虽由 `max_steps` 限制，单步 prompt 仍会随
数据列数增长。`max_steps` 不是成本边界。

### 接口

| 项 | 内容 |
| --- | --- |
| 请求字段 | `agent_max_tokens: int = 0`（0 = 不限制，保持既有行为） |
| CLI | `--agent-max-tokens N` |
| 终止原因 | 新增 `token_budget`（不得复用 `model_finished`） |
| `result.json` | `data.agent.budget = {limit, used, remaining, enforced, exhausted, unavailable}` |
| 报告 | `### 3.1 Agent 执行轨迹` 增加「token 预算」行 |

### 语义（必须先定义清楚）

1. **只约束模型调用**：预算检查发生在每次决策之前；工具执行不消耗 token，
   因此超限前的最后一次决策仍会执行完所选工具，结果不丢。
2. **`limit=0` 表示不限制**，`budget.enforced=false`，行为与 T2.12 逐字段一致。
3. **服务端未返回 `usage`**：`budget.unavailable=true`，运行继续并在 `warnings`
   写明「预算未生效」。不估算、不猜测 token——猜测值会变成假账。
4. **`used` 以客户端 `usage_summary().total_tokens` 为准**，不自行按字数折算。

### 验收标准（先写后测）

| 编号 | 标准 | 验证方式 |
| --- | --- | --- |
| A1 | 设限且超限：`terminate_reason == "token_budget"`，`budget.exhausted == true` | 单测：假客户端按调用累加 usage |
| A2 | 不设限：终止原因与 T2.12 一致，`budget.enforced == false` | 单测 + 既有 304 项回归 |
| A3 | `usage` 缺失：`budget.unavailable == true`，运行不中断，`warnings` 有说明 | 单测（FakeClient 无 usage） |
| A4 | 截断后轨迹仍完整、可重放（`trajectory_sha256` 可复算） | 单测 + 一次真实运行 |
| A5 | 成本可解释：`budget.used` 等于服务端 `usage.total_tokens` 累计 | 真实运行对照 `tokens` |
| A6 | 全量测试通过（当前基线 304 项） | `python run_tests.py --timeout 400` |

### 不做的事

- 不做单步 prompt 的 token 预估裁剪（属于 `observation.py` 的职责，已有 6000 预算）；
- 不做美元成本换算（价格随供应商与缓存命中变化，无法离线核实）；
- 不把预算失败包装成普通成功：超限必须能从 `terminate_reason` 看出来。
