### T2.2 改造要点（开工前必读）

目标：实现观察—决策—行动循环，使流程长度由模型决定。

| 项目 | 内容 |
| --- | --- |
| 新增 | `src/mtsa/agent_runtime.py`（已落地） |
| 决策输出 | `{"action": 工具名 或 "finish", "args": {...}, "reason": "..."}` |
| 终止条件 | 模型调 `finish`；步数达上限（默认 8）；无未执行工具且模型未结束；连续两次空转 |
| 接口 | 复用 `mtsa.tools` 的六个工具；准备层与收尾层固定，不进循环 |
| 硬约束 | 数值仍由代码产出；工具失败不得使整次运行崩溃（见 T2.7） |
| 回滚 | `--mode pipeline`（默认值）或直接不传 `--mode`；环境变量开关留到 T2.6 |

改造范围已界定，不在此范围内的部分不得擅自扩大：

| 层 | 节点 | 是否自主 |
| --- | --- | --- |
| 准备层 | 导入、规模检查、摘要、质量、场景识别、计划、清洗 | 固定 |
| 分析层 | 指标、频域、统计检验、异常、变化点、泄漏检查 | **模型自主** |
| 收尾层 | 图表、报告、证据校验 | 固定 |

## 立项前的硬性要求

沿用 T1.1 至 T1.8 已验证的纪律，新任务书必须写明：

1. **不改变已有结论的判据**。若必须改变，先做对照实验证明「判定不变」，否则如实否决并留下证据（参见 `doc/改进记录.md` 改进 #6 对 ADF 限幅的处理）。
2. **评估指标数值若发生变化，必须能解释来源**，且不得以放宽阈值为手段通过。
3. **验收标准须先写、后测**，不允许事后按实测结果回填标准。
4. 涉及外部依赖（模型服务、密钥）的能力，不得成为离线评估的必需项。
