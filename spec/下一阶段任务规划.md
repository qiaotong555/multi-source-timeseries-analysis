| # | 缺口 | 现状 | 会导致的错误结论 |
| --- | --- | --- | --- |
| 1 | **结论正确性** | 只统计「工具是否执行」（需求覆盖、规则覆盖），不统计「结论对不对」 | 把 `mean_need_coverage=1.00` 说成「分析质量达标」。实际 13 用例里 agent 比 pipeline 少 9.08 条结论，没人回答过这些结论里有没有真事件 |

理由：A/B 不改任何生产行为，只增加测量，风险最低，而且直接补上最大的证据缺口；

## 4. 任务卡

### A. 结论级评估（P0，预计 1 天）

| 项 | 内容 |
| --- | --- |
| 目标 | 把「执行了」升级为「结论对没对」：用真值标签给 agent 与 pipeline 的结论打分 |
| 输入 | `fixtures/labels_weather_v1.csv`（25 条：18 个异常点、2 个压力均值跳变、5 个数据质量事件）；两模式的 `result.json` |
| 方法 | 异常：按事件级合并连续点，算 Precision/Recall（口径对齐 `evals/run_evals.py` 的 holdout 指标）；变化点：位置容差 ±2 个采样点；趋势/季节性：标签未覆盖，改用 fixture 生成时注入的真值（斜率符号、季节振幅），不臆造 |
| 产出 | `evals/conclusion_eval.py`、`evals/conclusion_eval_results.json`、报告章节 |
| 验收 | 13 用例 × 2 模式各给出 P/R/F1；能直接回答「agent 相比 pipeline 漏掉几个真异常、误报几个」；标签未覆盖的类别明确标 `unlabeled`，不计分 |
| 风险 | 结论文本→结构化事件需要解析；宁可少算（标 unlabeled）也不猜 |
| 不改 | 不调整任何检测阈值；只读既有结果 |

### B. 结论差异溯源（P0，预计 0.5 天）

| 项 | 内容 |
| --- | --- |
| 目标 | 解释 agent 比 pipeline 少的 9.08 条结论到底少在哪 |
| 方法 | 逐用例按 `Conclusion.category` 对齐，输出「类别 × 模式」矩阵；每条差异标注原因：工具未执行 / 工具执行但无检出 / 参数不同 |
| 产出 | `evals/conclusion_diff.py`（或报告脚本）+ 一张缺口表 |
| 验收 | 差异 100% 归入三类原因，无法归因 ≤5%；结论写进 `doc/评估设计.md` |
| 价值 | 把「−23.3%」从数字变成可解释的结构 |

### C. 第二份数据（P1，预计 1–1.5 天）

| 项 | 内容 |
| --- | --- |
| 目标 | 验证结论不依赖单一 fixture 的采样结构 |
| 做法 | 新增 fixture：30 天 / 15 分钟采样 / 单站点 / 含一次时区或 DST 切换 / 10% 缺失 / 少量异常；同步生成标签 |
| 验收 | 同一份数据、同一 seed，pipeline 两次运行结论逐字段一致；agent 需求覆盖 ≥0.90；短样本导致的检验退化必须显式写进 `warnings`，不能静默给结论 |
| 风险 | 720 点做 STL/KPSS 会退化；这正是要测的，不允许靠调阈值掩盖 |

### D. 探针与重复（P1，预计 0.5 天）

| 项 | 内容 |
| --- | --- |
| 目标 | 给「范围选择」和「低频抖动」一个像样的样本 |
| 做法 | 探针 2 → 6（含开放式、风险式、对比式）；`guided`/`free` 各 5 次 × 6 用例 |
| 验收 | 给出 free 步数的分布（min/median/max 与出现频次），不再用单批极差下结论；总运行 ≤ 30 次 |
| 成本 | 约 12 万 token 量级，先按 `--agent-max-tokens` 限流 |

### E. 股票 Agent（P2，预计 3–5 天，需用户确认）

| --- | --- |

### F. 多模型对比（P2，预计 1 天）

| 项 | 内容 |
| --- | --- |
| 做法 | 同一 13 用例，至少两个模型；固定 `guided`、`rule` 计划、同 seed |

- 金额换算需要维护供应商价格表，离线无法核实，暂不做。
