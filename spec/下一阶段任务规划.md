### 8.1 阶段 C：正确性修复（P0/P1，合计约 3 天）

#### C1 单位推断修复（P0，1 天）

**现象**：R08（DWD 柏林-泰格尔，°C）在 2024-04-26 前后 7 天中位数 5.700 → 18.200
（比值 3.193），被判定为华氏度段，`(x-32)/1.8` 改写 5,977 行，区间中位数变成 -9.222。
独立来源 R01 对照 r=0.9973、偏差 0.54°C，两窗同样升温约 12°C，证明是真实季节变化。

**根因链**（三处叠加）：

1. `quality.detect_level_shifts` 用 `window=max(12, n//50)`（小时级约 175 点 ≈ 7 天）
   的中位数比值判单位，春季升温可以轻松超过 2.0；
2. `scenarios/weather.py` 接受比值 ∈ [2.4, 4.2] 即安排换算；
3. 只有一个转移点时按开放区间处理，直接把之后全部数据换算。

**方案（需先做离线对照，不直接改线上）**：

| 判据 | 内容 |
| --- | --- |
| J1 阶跃 | 边界两侧**短窗**（小时级 ±6 点、日级 ±3 点）中位数差 / 局部稳健 σ ≥ 6 |
| J2 双侧稳定 | 两侧窗内趋势斜率接近 0；窗内标准差比 ∈ [0.5, 2] |
| J3 仿射一致 | °F→°C 是仿射变换，p10/p50/p90 换算前后的相对关系应一致（离散度 <10%） |
| J4 物理合理 | 换算后落在变量合理区间（温度 -60..60°C），且中位数比换算前更接近相邻正常段 |
| J5 开区间 | 只有单侧转移点时**默认不自动换算**，只报 `POSSIBLE_UNIT_CHANGE` 并要求人工确认；成对转移点才自动换算 |

J5 是行为变化：会降低自动修复的召回，但避免「一次误判污染整份数据」。成对转移点按
`unit_change_autoconvert`（默认 true）决定是否自动换算；**开区间无论配置如何都不自动换算**，
只输出警告。

**验收（先写后测）**：

| 编号 | 标准 | 验证方式 |
| --- | --- | --- |
| A1 | R08 不再发生任何 `unit_conversion`，温度与 `data.csv` 逐点一致（max|Δ|=0） | 重跑 R08，检查 `clean.unit_conversions == []` |
| A2 | Demo 的 `STA_A` 案例仍转换 713 行，median 76.9392 → 24.9662 | 重跑案例，对照第 32 章数字 |
| A3 | R08 结论恢复夏高冬低（峰值月 7 或 8） | 检查季节性结论 |
| A4 | v2 门禁 24/24 不变 | `python -m evals.conclusion_gate_eval` |

2. 零检出结论：`detect_anomalies` / `detect_change_points` 执行且结果为 0 时，
   输出「未发现异常 / 未发现变化点」，并注明方法与阈值。
3. 只**新增**结论类别与条目，不删除、不改写既有结论，避免破坏历史对比。

#### C4 缺口定位（P2，0.5 天）
