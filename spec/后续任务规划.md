# 项目后续任务规划

> 规划对象：`<repo>`
>
> 规划日期：2026-10-23（Asia/Shanghai）
>
> 规划目标：在不破坏已有确定性分析能力的前提下，把当前 Agent 原型逐步接入主流程，先完成天气正式场景的可控、可评估、可复现 Agent 模式。股票场景暂不进入本轮 Agent 实现。

## 1. 总体目标

最终形成两种可以明确区分的运行模式：

```text
pipeline：固定、确定性、可作为基线和兜底
agent：模型选择分析工具，但数值计算仍由代码完成
```

Agent 的自主范围只放在分析层：

```text
固定准备层：导入 → 规模 → 摘要 → 质量 → 场景 → 计划 → 清洗
Agent 分析层（天气）：指标、频域、统计检验、异常、变化点
股票的未来数据泄漏检查保留在已有 pipeline 能力中，但暂不接入 Agent。
固定收尾层：图表 → 报告 → 证据校验 → 落盘
```

不允许模型决定数据清洗顺序、不允许模型直接计算数值、不允许因为 Agent 改造而删除固定流水线。

## 3. 阶段 0：基线冻结与未提交修改审查

### 目标

在继续开发前固定当前基线，避免把未提交修改、缓存结果和历史轨迹混为正式结论。

### 工作内容

1. 保存当前 Git 状态和 diff 摘要；
2. 冻结本轮范围：Agent 只实现天气，股票 Agent 暂不实现；
3. 审查 `src/mtsa/tools.py` 的全量分析扩展逻辑；
4. 核对底层实际分析项、默认计划项和文档中的 12/13/14 项说法；
5. 运行 204 项测试；
6. 记录当前天气 pipeline 结果作为回归基线；
7. 在有模型配置时重新运行一次真实天气 Agent 联调；
8. 决定未提交修改是保留、调整还是回退。

### 验收标准

- 测试仍为全通过；
- 工具扩展不改变锁定参数；
- 原有 pipeline 数值结果不变；
- 文档明确工具数量、分析项数量和计划项数量的区别；
- 未提交修改有明确处理结论。

## 4. 阶段 1：完成 T2.2 Agent 主流程接入

### 目标

把现有 `AgentRunner` 从独立原型接入正式分析流程，但先不扩大自主范围。

### 主要改动范围

```text
src/mtsa/engine.py
src/mtsa/cli.py
src/mtsa/agent_runtime.py
tests/test_agent_runtime.py
新增集成测试
```

### 实现要求

1. 准备层仍由引擎固定执行；
2. Agent 只接管天气场景的五个工具：`compute_metrics`、`analyze_spectrum`、`run_stat_tests`、`detect_anomalies`、`detect_change_points`；
3. 股票专属 `check_lookahead` 不进入本轮 Agent；股票场景请求 Agent 模式时明确拒绝，不静默降级；
4. 收尾层仍固定执行；
5. 工具结果同时保留完整数据和模型摘要；
6. 轨迹至少记录动作、参数、理由、结果状态和耗时；
7. Agent 没有模型客户端时要给出明确错误或由后续 `auto` 模式回退；
8. 工具失败不得让整个 Agent 循环无提示崩溃。

### 验收标准

- 能从正式入口启动一次 Agent 分析；
- 天气场景可以使用 Agent，股票场景请求 Agent 时返回明确的不支持错误；
- 真实模型或测试替身能完成至少一条闭环；
- `engine.py` 不再需要手工调用临时 `_demo_agent.py` 才能运行 Agent；
- pipeline 原有结果逐字段不变；
- 每步 Agent 理由非空；
- 运行轨迹可序列化；
- 至少有一条工具失败后继续或明确结束的测试。

## 5. 阶段 2：T2.3 观察摘要器与 T2.4 安全边界

两个任务可以并行，但必须先定义共同的数据结构。

### T2.3 观察摘要器

新增：

```text
src/mtsa/observation.py
```

负责生成：

- 数据列、类型、采样率和质量问题摘要；
- 场景候选和置信度；
- 计划参数；
- 已完成工具清单；
- 尚未完成工具清单；
- 最近结果摘要；
- 更早步骤的压缩摘要。

验收要求：

- 不包含原始数组；
- 单步摘要有长度上限；
- 7 步轨迹总上下文目标低于 6000 token；
- 明确列出已执行工具，避免重复选择；
- 测试能验证长轨迹不会无限增长。

### T2.4 决策安全边界

新增：

```text
src/mtsa/agent_guards.py
```

负责：

- 工具白名单；
- 参数白名单；
- 锁定参数保护；
- 步数上限；
- 重复调用策略；
- 越界拒绝事件；
- 连续越界终止；
- 资源和费用预算预留。

验收要求：

- 未知工具被拒绝；
- 未知参数被拒绝；
- 修改 `anomaly_threshold`、`change_point_sse_ratio`、`close_column` 等锁定参数被拒绝；
- 拒绝原因回灌模型；
- 越界次数可统计；
- 不能因为拒绝而静默完成。

## 6. 阶段 3：T2.7 失败恢复

### 目标

让分析层单个工具失败时，系统仍然能够完成可审计的运行。

### 设计

- 工具异常转换为结构化失败结果；
- Agent 可以选择其他工具；
- 允许在参数合法范围内重试；
- 可以明确跳过某项分析；
- 报告和 `result.json` 标记失败、跳过和未执行三种状态；
- 准备层失败仍直接终止，因为无法安全降级。

### 验收标准

- 注入工具异常后主流程不崩溃；
- 失败原因进入轨迹和报告；
- 失败分析不会被误写成成功；
- 重试次数有上限；
- 有专项测试覆盖工具失败、重试、跳过和最终终止。

## 7. 阶段 4：T2.5 轨迹持久化与重放

### 目标

解决 Agent 每次自由决策导致的不可复现问题。

### 主要内容

1. `result.json` 增加 `data.agent_trajectory`；
2. 保存模型标识、动作、参数、理由、摘要、状态和耗时；
3. 计算轨迹哈希；
4. 增加 `--replay`；
5. 重放时不调用模型，只按轨迹调用工具；
6. 对比原运行和重放结果；
7. 排除 `run_id`、时间戳等非确定字段后进行逐字段或逐字节比较。

### 验收标准

- 保存的轨迹可以独立读取；
- 重放不需要模型 API；
- 重放结果与原结果一致；
- 工具随机源、时间源和浮点序列化规则经过审计；
- 重放失败时给出具体差异路径。

## 8. 阶段 5：T2.6 双模式并存

### 目标

正式提供：

```text
--mode pipeline
--mode agent
--mode auto
```

行为约定：

- `pipeline`：现有固定流水线，作为回归基线；
- `agent`：使用 Agent 循环，缺少模型配置时明确失败；
- `auto`：有模型配置使用 Agent，否则回退 pipeline，并在结果中记录回退原因。

### 验收标准

- 三种模式的入口和结果字段明确；
- `pipeline` 模式与 T1.8 基线逐字段一致；
- `auto` 回退行为可测试；
- Agent 模式的轨迹和未执行分析在结果中可见；
- 文档不把三种模式混为一种行为。

## 9. 阶段 6：T2.8 Agent 指标与 T2.9 对照实验

### Agent 指标

至少增加：

- 平均步数；
- 终止原因分布；
- 关键分析覆盖率；
- 轨迹可重放率；
- 越界拒绝次数；
- 工具失败率；
- Agent 模式耗时；
- 模型 token 或调用成本（可获取时）。

### 对照实验

复用已有天气问题集，分别运行天气 pipeline 和天气 agent，比较：

- 关键分析覆盖率；
- 结论条数和证据数量；
- 耗时；
- token 成本；
- 轨迹长度；
- 重放成功率；
- 失败和遗漏案例。

### 验收标准

- 指标按模式分栏，不能混算；
- pipeline 原有 25 项指标口径不变；
- 至少 9 个天气用例完成两模式对照；
- 结论同时报告 Agent 的优点和劣势；
- 缺少真实模型配置时，使用 Mock 的结果必须明确标注，不能冒充真实模型结论。

## 11. 总体验收门槛

全部 Agent 改造完成前，必须同时满足：

1. pipeline 模式下原有 25 项指标与基线逐字段一致；
2. Agent 轨迹长度可变，每一步有非空理由；
3. 任意已保存轨迹可以离线重放；
4. 关键分析覆盖率达到预先设定的门槛，建议不低于 0.80；
5. 工具失败、跳过和未执行状态可区分；
6. 越界动作可拦截并留痕；
7. 对照实验同时报告 Agent 的收益和代价；
8. 所有结果按 pipeline/agent 模式分栏；
9. 文档、代码、测试和最终报告口径一致。

## 12. 推荐的下一次实际开发顺序

下一次开始编码时，建议严格按下面顺序：

1. 先审查 `tools.py` 未提交修改和分析项数量口径；
2. 固定 pipeline 回归基线；
3. 将 `AgentRunner` 接入 `engine.py`；
4. 增加 Agent 主流程集成测试；
5. 实现观察摘要器和安全边界；
6. 补齐失败恢复；
7. 实现轨迹落盘与离线重放；
8. 增加三种 CLI 模式；
9. 扩展 Agent 指标；
10. 完成两模式对照实验；
11. 最后统一文档并生成最终报告。

任何阶段如果发现 pipeline 结果发生变化，应先暂停 Agent 扩展，定位回归原因，不能通过修改阈值来掩盖差异。
