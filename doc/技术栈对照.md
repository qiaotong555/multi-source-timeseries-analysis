# 技术栈对照（课程推荐 → 本项目）

课程推荐的是**技术清单**，不是验收清单：14 项里有「或」关系（Pandas/Polars、Matplotlib/Seaborn
与 Plotly 二选一即可）、有标注「可选」（ruptures、vectorbt）。逐项凑齐只会增加故障面；
评分表真正要看的是**选型有理由**。本文逐项给出理由与证据。

## 2. 本轮补的那一项

`mtsa-api`：提交 → 轮询 → 取 `result.json` / 产物。边界写在 `src/mtsa/api.py` 的模块
docstring 与 `doc/接口与字段.md` 第 7 节：不做业务逻辑、不做持久化、不做取消、单 token。

## 3. 两处「不是照抄」的地方

**Python 3.11 → 3.12+**：`numpy>=2.5` 与 `scipy>=1.18` 都要求 3.12+（CI 实测 3.11 装不上）。
降到 3.11 要放宽两者的下界，并整轮重跑 512 项测试 + 24/24 门禁 + 37/37 鲁棒性 + 80/80 真实数据，
代价 2–3 天且数值断言可能漂。**处置**：保留 3.12+，`requires-python` 让 pip 给出清晰报错，
Dockerfile 固定 3.13 保证容器内可跑，提交说明第一段主动写明。

**LangGraph 不引入**：本项目单链、最多 8 步、6–18 秒同步跑完、5 个工具串行依赖；
图编排的收益（并行分支、断点续跑、人工卡点、持久化快照）一条都用不上，代价是改写
轨迹哈希 / token 预算 / 离线重放三套已验证机制，并让 24/24、37/37、80/80 全部失去可比性。
**处置**：不引入；等价能力由「确定性状态机 + `events` 覆盖矩阵 + 轨迹重放」承担，
论证见 `doc/架构设计.md` 第 3 节。

## 4. 不引入的四项

| 不引入 | 理由 |
| --- | --- |
| scikit-learn | 会打掉现有卖点：异常判定是「稳健 z + 记录 method 字符串」，可复现可审计；换成 IsolationForest 引入随机性与黑盒打分。预测线已用 seasonal_naive / MA / drift 收口 |
| Matplotlib / Seaborn | 换渲染后端 = 重做全部图表 + 重跑图表测试；Plotly 已在推荐列表内。**已知风险**：kaleido 依赖真实浏览器（镜像装了 chromium），这是当前最脆的一环 |
| ruptures | 标「可选」；换判据要重新标定变化点曲线。它适合离线全局最优（Pelt/Binseg），不适合逐点在线判定 |
| vectorbt | 标「可选」；股票 Agent 处于暂缓状态，无需求 |

## 5. 一句话

**用推荐的 8 项、补 1 项、其余 5 项写明「为什么不用」——这比凑齐 14 项更能说明选型能力。**
