# 项目说明书

> 项目：多源时序数据量化分析与可视化 Agent
> 版本：2026-10-24（T2.13 + 方案 1 + 方案 2 完成后）
> 适用场景：天气（正式）；股票仅支持固定流水线，Agent 暂不实现
> 读者：需要快速判断「它能做什么、做到什么程度、怎么复现」的人

---

## 1. 一句话定位

输入一份带时间列的多源数据和一个自然语言问题，系统自动完成数据体检、清洗、量化分析、
异常/变化点检测与可视化，输出**每条结论都绑定证据**、可复现、可回放的分析报告；同一套引擎
提供两种运行方式：**固定流水线（pipeline）**与**模型编排工具（agent）**。

它不是一个「让大模型直接读数据、随口给结论」的聊天机器人。数值全部由代码计算，
模型只决定「先做哪项分析、再做哪项」，且只能在白名单工具内选择。

### 能回答的问题

- 这份数据的结构是什么？时间轴是否连续、有没有缺失/重复/乱序/单位异常？
- 温度（或其他指标）的趋势方向、季节振幅、峰谷月份是什么？
- 哪些时刻是异常点？哪些区段是持续异常？变化点在哪里？
- 各列之间是否相关、是否存在滞后关系？
- 结果能否复现？每条结论对应哪个数字、哪个文件？

### 不做什么

- 不做预测（不输出「未来会怎样」）；
- 不做因果推断；
- 股票 Agent 未实现（请求会返回 `AGENT_SCENE_UNSUPPORTED`）；
- 不做多模型对比；
- 不把合成数据上的结论直接外推为真实业务结论。

## 2. 输入与输出

### 输入

| 项 | 说明 |
| --- | --- |
| 数据文件 | CSV（UTF-8 / UTF-8-BOM / GBK 均可），必须有可解析的时间列 |
| 场景 | `weather`（温度/湿度/气压/风速/降雨）、`stock`（仅 pipeline），或自动识别 |
| 问题 | 一句自然语言，例如「分析温度的趋势、季节性和异常点，并检测变化点」 |
| 可选参数 | 时间列、数值列、分组列、随机种子、计划参数覆盖、运行模式、超时、token 上限 |

### 输出（每次运行一个目录）

```text
<output_dir>/
├── result.json     # 机器可读：状态、数据摘要、指标、异常、变化点、结论、证据、Agent 轨迹
├── report.md       # 人读报告：数据概况、质量、分析结论、图表索引、证据表
└── figures/        # 图表（PNG）
```

`result.json` 的关键字段：

| 字段 | 含义 |
| --- | --- |
| `status` | `succeeded` / `failed`；失败也落盘，并给出 `error.code` |
| `data.profile` | 行列数、时间范围、采样间隔、数值/分组列 |
| `data.quality` | 缺失、重复、乱序、采样缺口、异常候选、单位变化等 |
| `data.metrics` / `spectrum` / `tests` | 指标、频域、统计检验原始结果 |
| `data.anomalies` / `change_points` | 检测结果（含方法、分数、前后值） |
| `conclusions` | 结构化结论（类别、文本、`evidence_ids`） |
| `evidence` | 证据条目（指标名、数值、来源文件/位置） |
| `data.agent` | Agent 轨迹：步数、工具、拒绝事件、token、重放哈希 |

## 3. 全流程

```text
准备层（固定，不由模型决定）
  导入 → 规模检查 → 数据摘要 → 质量检查 → 场景识别 → 计划 → 清洗
        ↓
分析层
  pipeline：五个分析单元按固定顺序全部执行
  agent   ：模型在白名单内逐步选择工具；每步结果摘要回灌后再决策
        ↓
收尾层（固定）
  图表 → 报告 → 证据校验 → result.json / report.md 落盘
```

### 准备层

- **导入**：编码探测、分隔符与表头识别、时间列解析、超限拒绝（默认 20 万行）。
- **质量**：缺失率、重复时间戳、乱序、采样缺口、单位变化、极端值候选。
- **场景识别**：按列名与问题关键词判定天气/股票；识别不确定时保留多候选并给出理由。
- **计划**：规则计划（默认）或 LLM 计划（可选）；计划只决定「分析哪些项、用什么参数」，
  且参数必须在场景白名单内。
- **清洗**：按分组透视、缺失插值、非有限值处理、单位统一；所有操作写入 `clean.operations`。

### 分析层（天气五个工具）

| 工具 | 产出 |
| --- | --- |
| `compute_metrics` | 均值/标准差/分位数、OLS 斜率、Mann-Kendall、趋势/季节性结论 |
| `analyze_spectrum` | 周期图/频谱峰值，日周期、年周期判断 |
| `run_stat_tests` | ADF/KPSS、自相关、正态性等检验结果 |
| `detect_anomalies` | 稳健残差 Z 值超阈值的异常点 |
| `detect_change_points` | 均值突变/方差突变/单位跳变 |

### 收尾层

- 图表字段映射（时间轴、数值轴、分组）；
- Markdown 报告：数据概况、质量问题、逐项结论、图表、证据表；
- **证据校验**：每条结论必须引用存在的 `evidence_id`，否则该结论不进入最终结果
  （`无证据结论数` 是主评估的硬指标，当前为 0）。

## 4. 两种运行模式

| 维度 | pipeline | agent |
| --- | --- | --- |
| 谁决定分析顺序 | 固定代码 | 模型（白名单内） |
| 数值由谁算 | 代码 | 代码（模型看不到原始数组） |
| 步数 | 固定 | 4–8 步，取决于问题与模型 |
| 成本 | 无模型调用 | 记录 token；可设上限 |
| 可复现 | 完全确定 | 轨迹 + `trajectory_sha256` + `--replay` 离线重放 |
| 适用 | 生产默认、评估基线、兜底 | 需要按问题裁剪分析项时 |

### Agent 的范围控制

- 白名单：天气五个工具；股票的工具不进入本轮 Agent。
- `guided`（默认）：先用问题关键词算出「至少要做哪些工具」，未覆盖前不允许结束；
  下限之外最多追加 1 步（`agent_max_extra_steps`）。
- `free`：范围完全由模型判断，步数会波动，仅用于研究对照。
- 硬边界：不能重复执行已成功的工具；工具参数不可由模型改写（`anomaly_threshold`
  等锁定）；越界选择记 `scope_exceeded`，不会执行。

### 失败与降级

- 单个工具失败：可重试 1 次；仍失败则记录状态并继续，不使整次运行崩溃。
- 模型不可用 / 场景不支持：`AGENT_UNAVAILABLE` / `AGENT_SCENE_UNSUPPORTED`，不静默回退。
- 任意未覆盖异常：顶层护栏收敛为 `INTERNAL_ERROR`，`details.node` 指向失败节点，
  且保证 `result.json` 落盘。

---

## 5. 关键设计决策

1. **数值与叙述分离**：模型只看到工具摘要，不接触原始数组，也不能改检测参数。
2. **结论必须绑定证据**：没有证据的结论不进入最终输出；证据可追到具体指标与文件。
3. **默认不动检测阈值**：任何阈值/判据改动必须先做对照实验，证明判定不变或解释变化。
4. **失败可控**：坏输入要么明确拒绝（错误码），要么成功但带 warning；不崩溃、不静默。
5. **两种模式共用准备层与收尾层**：Agent 只替换分析层的编排，避免「两套系统」漂移。
6. **评估先写后测**：阈值在看到结果前冻结；不达标如实记录，不回调。

### 6.2 结论级评估（13 个天气用例）

- 异常点级 P/R/F1：pipeline 与 agent 均为 **0.1295 / 1.0000 / 0.2293**；

  无法归因 0 条。这说明差异来自「没看」，不是「看了但结论不同」。

> 该数据集的异常点很密集（25 条标签、2 年小时级），点级 Precision 低是「检出多、标签少」

## 7. 已知限制（按影响排序）

1. **真实数据只证明了工程可控，未证明结论正确**。C1 已修掉最严重的单位误判
   （R08 零换算、峰值月恢复 8 月），C2 修掉多站点判重（17,568 → 0），C3 补齐质量与
   零检出结论（需求覆盖 0.800 → 1.000），C4 补齐缺口定位（可定位 Recall 0.500 → 1.000）；
   但 L2 仍为空，异常 P/R/F1 无法计分（下一步 D1，见 `spec/未来规划.md`）。
2. **变化点精度不足**。v2 上 6 检出 / 2 真实：真实跳变被二分切成两段、年周期弱分割、
   降雨单点极端值被判为方差突变。F1 恰好 0.50，**下一轮多 1 个误报即失败**。
3. **长时间持续异常会漏检**。8 小时持续段被 24 小时中心滚动中位数部分吸收，
   残差 z 只有 4–6.6（阈值 8），v2 中漏掉 1 个事件。
4. **Agent 与 pipeline 的结论级指标相同，不等于能力相同**。guided 下限固定了必做工具；
   4 次中 3 次缺 `run_stat_tests`（`budget_exhausted` 指追加步数，不是 token），
   只是该工具不影响被评分的四类结论。
5. **统计效力有限**。v2 只有 4 个问题、2 个站点；成功率 4/4 的 Wilson 区间是 [0.51, 1.0]，
   不能据此宣称「真实数据上 100% 成功」。
6. **成本只有 token，没有金额**；预算在调用后累计，可能小幅超限。
7. **股票场景只有 pipeline**，Agent 未实现；本说明书不把股票算作 Agent 能力。
8. **v2 不是严格盲测**：生成器在固定前经过构造性修订，结果只能表述为「固定版 v2 上的表现」。

## 8. 快速开始

### 8.1 一键演示（推荐先跑这个）

```bash
python scripts/demo.py
```

- 默认输入 `fixtures/weather_v1.csv`，问题为「分析温度的趋势、季节性和异常点，并检测变化点」；
- 同时跑 pipeline 与 agent；缺模型时自动跳过 agent 并说明原因；
- 输出 `artifacts/demo/demo_summary.md`（人读）与 `demo_summary.json`（机器可读）。

```bash
# 只跑确定性流水线（不需要模型）
python scripts/demo.py --mode pipeline

# 换数据与问题
python scripts/demo.py --input fixtures/weather_eval_v2.csv   --question "找出温度湿度的异常、气压的突变，并说明季节规律" --mode both
```

### 8.2 命令行

```bash
# 固定流水线
PYTHONPATH=src python -m mtsa.cli run --scene weather   --input fixtures/weather_v1.csv --question "分析温度的趋势、季节性与极端事件"

# Agent（需配置 MTSA_LLM_BASE_URL / MTSA_LLM_API_KEY / MTSA_LLM_MODEL）
PYTHONPATH=src python -m mtsa.cli run --mode agent --scene weather   --input fixtures/weather_v1.csv --question "分析温度的趋势、季节性和异常"   --agent-max-tokens 8000

# 离线重放一次 Agent 运行（不调用模型）
PYTHONPATH=src python -m mtsa.cli run --replay artifacts/<run_id>/result.json
```

### 8.3 评估

```bash
PYTHONPATH=src python -m evals.run_evals                 # 主评估（29 项）
PYTHONPATH=src python -m evals.robustness_eval           # 37 个坏输入
PYTHONPATH=src python -m evals.conclusion_gate_eval      # 独立结论门禁（24 项）
PYTHONPATH=src python -m evals.conclusion_gate_eval --pipeline-only   # 离线版
```
