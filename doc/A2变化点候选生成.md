# A2：变化点候选生成器的三种改法，以及为什么都不该上

> 2026-11-03。结论先行：**换候选生成器不解决问题，方案否掉。**
> 本轮真正交付的是一处确定的缺陷修复（局部散布为 0 时的误报），
> 以及一份「为什么不做」的量化记录——包括一次差点把它做进去的过程。

---

## 一、为什么会有这一轮

A1 把过检修好之后，暴露出一个更根本的现象：**17 份真实天气数据上，均值突变只检出 4 个，
而且全在 1.3–2.1σ**。当时我写下的解释是「季节项主导，SSE 比例提不出候选」。

这一轮要验证的假设是：**如果换一个候选生成器，真实数据能不能真的检出东西。**

三种改法，全部实现并测量：

| 方案 | 候选怎么来 | 假设 |
| --- | --- | --- |
| B 窗口中位数扫描 | 两侧各 h 点的中位数差，取局部极大值 | 不依赖方差解释比例，季节项干扰小 |
| C 粗到精 | 先用 B 找「哪里有水平差」，再用 SSE 在局部段内定到哪一点 | B 定位不准，SSE 定位准，组合起来 |
| D 兜底 | 先跑现在的 SSE；一列一个都没接受时才用 C | 保守优先，静默时才升级 |

---

## 二、B 的直接失败：中位数大窗口不定位

`|median([k, k+h)) − median([k-h, k))|` 在台阶附近不是尖峰，而是一段**平台**：

- 右窗中位数只在台阶越过窗口一半时才翻转，左窗同理；
- 于是从 `k − h/2` 到 `k + h/2` 的整段，这个差值都≈台阶高度；
- 平台的峰顶由数值噪声决定，落点与真实位置无关。

v2 上的实测：真值在 1440 与 4800，B 报出 1389（偏 51 小时）和 1613（偏 173 小时），
**两个都超出 ±2 小时的匹配容差，F1 = 0.000**。

这条不是参数没调好：h 越小平台越窄，但 h 小于 3 个周期时中位数估不准水平，
两个要求互斥。**用中位数做的窗口扫描天然不能定位。**

---

## 三、C 的改进与它没解决的问题

C 用 SSE 在局部段内重新定位，v2 上定位恢复（1440 / 4800 命中），并且：

| 项 | A 现状 | C 粗到精 |
| --- | --- | --- |
| v2 均值通道 F1 | 1.000 | 0.800（多 1 个温度点，3.35σ） |
| 网格总体检出率 | 0.53 | **0.72** |
| 网格 Δ=12 命中 | 0.60 | **1.00** |
| 网格 Δ=8 命中 | 0.00 | **0.80** |
| 网格 Δ=0 伪报 | 0.00 | 0.00 |
| 真实数据检出 | 0 | **23** |

看起来是一次干净的灵敏度提升。**但注入台阶的对照把它否掉了。**

---

## 四、决定性证据：注入台阶能否检出

在真实数据上注入已知台阶，看三种方案能不能命中（误差 ≤ 3 个采样点）：

| 数据 | 频率 | Δ=8 °C | Δ=12 °C |
| --- | --- | --- | --- |
| R01 柏林 | 小时 | A 偏 +2956；C **未检出**；D 偏 +2956 | A 未检出；C 偏 +6；D 偏 +6 |
| R10 多伦多 | 小时 | 三者全未检出 | A 未检出；**C +0 ✓**；D +0 ✓ |
| R03 凤凰城 | 日 | 三者全未检出 | 三者全偏 +90 |
| R06 纽约中央公园 | 日 | 三者全偏 −993 | A −30；C −49 |

三条读数：

1. **合成网格上的灵敏度提升没有迁移到真实数据。** C 在 v2 上能命中 8 hPa，在 R01 上
   连 8 °C 都检不出、12 °C 偏 6 个点。网格用的是干净合成集，没有年周期、没有真实天气的
   多尺度结构；只在那种数据上成立的灵敏度是假的。
2. **日频数据上三种方案全脱靶。** 日频数据 `seasonal_period=0`，`h = 2×min_len` 会跨过
   半个季节；窗口中位数差量的是季节差，不是台阶。
3. **C 在真实数据上多出来的 23 个点没有任何标注可以验证。** 拿不出正确性证据的输出，
   不能因为「比以前多了」就当成能力。

---

## 五、根因：贪心递归会被「切不动的父段」挡住

R01 注入 +12 °C 在 4392，局部信噪比 3.88（显著），但**根本没成为候选**：

| 切点 | 残差平方和 | 占 SST |
| --- | --- | --- |
| 2841（季节分界） | 476,827 | **0.463** ← 全局最小 |
| 4392（注入台阶） | 530,742 | 0.515 |
| 507 | 850,676 | 0.826 |

第一次分割必然选 2841（季节分界解释的方差比台阶多）。切完之后，右段 `[2841, 8784]`
是「4 月→12 月」的 U 形季节曲线，**一刀切下去解释不了 30%，比例判据不通过，
递归就不再往下走了**——藏在里面的台阶永远见不到。

这不是深度不够：`_segment` 在父段被拒时直接返回，加深度也没用。这是贪心二分 +
停止规则的固有缺陷。

---

## 六、真实数据里到底有没有台阶

在换生成器之前先测了上限：对 17 份数据的每一列，按 `min_len/4` 步长扫遍所有位置，
记录局部信噪比的最大值。

- 全库最高 **5.78**（R13 湿度），多数列在 1–4；
- 靠前的几个「跳变」是 25.00 / 30.00 / 20.50 这类整数差，一验就露馅：
  R13 湿度 4161 附近是 52→66→80→83 的雨过程，R02 气压是 2.45 hPa 的天气尺度起伏。

再用「突变性」区分：真台阶在小窗口上也显著，天气尺度漂移随窗口变长才变大。

| 位置 | SNR @ h=24 / 72 / 168 / 438 | 判读 |
| --- | --- | --- |
| R01 气压 **注入 +18**（正对照） | **20.4** / 6.2 / 4.0 / 3.5 | 突变 |
| R13 湿度 4161 | 0.4 / 3.7 / 4.3 / 5.8 | 随窗口变大 → 漂移 |
| R15 温度 7887 | 1.5 / 8.6 / 3.3 / 4.4 | 同上 |
| R17 温度 15624 | 0.3 / 3.0 / 1.0 / 1.0 | 同上 |
| R04 气压 6807 | 0.7 / 3.5 / 2.2 / 4.2 | 同上 |

**真实天气数据里，被 3σ 以上的「水平差」几乎都是天气尺度的冷暖/干湿交替，不是结构突变。**
把它们报出来不是能力，是把天气当故障。

---

## 七、结论与决定

1. **不换候选生成器。** 三种改法都试过：B 不定位、C 的灵敏度不迁移、D 与 C 等价。
   当前 SSE + 局部信噪比门槛保持不变，v2 F1 仍是 0.6667。
2. **真实数据上的静默是正确行为**，不是缺陷。它反映的是「一年期天气序列里没有超过 3σ
   的突变」，而不是「检测器太弱」。
3. **但要承认一个真实缺陷**：R01 注入 12 °C 台阶（3.88σ）检不出，原因是贪心递归被
   切不动的父段挡住。这条写进已知限制，不掩盖。要修它需要换分割策略
   （PELT / 滑动窗口精确分割），而 A1 已经量过：在强自相关序列上换统计判据的代价
   是精确率崩塌（BIC 25 个点、Pettitt 18 个点），所以不在本轮做。

**如果将来真要解决「真实数据上的台阶检测」，需要的不是更好的统计量，而是更好的信息：**

- 多年基线（R17 有 7 年，其余只有 1 年）——1 年数据里 5–12 °C 的台阶与年周期不可分离；
- 或显式的季节模型（STL 分解后对趋势项做分割），代价是历史结果全部重算；
- 或换问题定义：不做「结构突变」，改做「天气过程分段」（冷锋、雨季开始），
  但那是另一个产品，需要另一套真值。

## 八、本轮实际交付：一处确定的缺陷修复

实验中撞到一个真 bug：**局部散布为 0 时给出 `snr = inf`**。

降水列有整段为 0 的区段，`_deseason_dev` 出来全是 0，MAD = 0，于是
`jump > 0 → snr = inf`，任何 0.1 mm 的中位数差都被报成最高置信度变化点。

生产路径确实可达：构造一条「常数 0 → 常数 0.1」的序列，SSE 会提出切点（SSE 降到 0），
门槛给出 `inf`，于是报出。真实数据上生产路径没触发（SSE 没提出这些候选），
但本轮实验里候选更密的扫描变体在每个降水列上各触发 2–3 个——**同一个函数，
门槛一放宽就暴露**。

修法：`scale <= 0` 时返回 `snr = 0`（不判显著）。**没有噪声模型就没有证据**，
退化序列不该产生「无穷大置信度」。已加回归测试 `test_constant_block_does_not_produce_change_point`。
