# 接口与字段

## 1. 命名

| 对象 | 格式 | 本课题取值 |
| --- | --- | --- |
| `task_id` | 小写 `snake_case` | `multi_source_timeseries_analysis` |
| `capability_id` | `<domain>.<action>` | `science.multi_source_timeseries_analysis` |
| `run_id` | `run_<日期>_<8位随机>` | `run_20260927_a1b2c3d4` |
| Python 类 | `PascalCase` | `AnalysisRequest` |
| 函数与字段 | `snake_case` | `detect_change_points` |
| 常量 | `UPPER_SNAKE_CASE` | `MAX_RERUN` |
| JSON 字段 | `snake_case` | `request_id` |

已发布字段和接口不得直接改名；变更需同步修改 schema、实现、测试和本文档。

## 2. 公共字段

所有顶层响应包含：

```text
request_id   str   请求唯一标识
task_id      str   固定 multi_source_timeseries_analysis
run_id       str   本次运行标识
status       str   queued/running/waiting_for_input/cancel_requested/succeeded/failed/cancelled
data         obj   业务数据（成功时存在）
evidence     list  结论—证据绑定
datasets     list  输入数据集版本信息
artifacts    list  产物清单
warnings     list  告警
events       list  节点执行轨迹
error        obj   code/message/details（失败时存在）
```

## 3. 请求模型 `AnalysisRequest`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `request_id` | str | 是 | 幂等键 |
| `input_path` | str | 是 | 输入文件路径 |
| `scene_id` | `weather`/`stock`/`null` | 否 | 缺省时自动识别，置信度不足则报错 |
| `time_column` | str/null | 否 | 缺省由 profiler 推断 |
| `value_columns` | list[str]/null | 否 | 缺省由 profiler 推断 |
| `group_column` | str/null | 否 | 分组字段（站点、股票代码等） |
| `unit` | str/null | 否 | 单位说明 |
| `sampling_interval` | str/null | 否 | 采样间隔（pandas 频率串，如 `1h`、`1D`） |
| `question` | str | 是 | 自然语言分析问题 |
| `param_overrides` | dict | 否 | 覆盖场景适配器给出的计划参数（如 `{"anomaly_threshold": 7.5}`）。键必须是该场景计划中已存在的参数；出现未知键时中止并返回 `invalid_param_override`，不静默忽略 |
| `seed` | int | 否 | 默认 20260927 |
| `output_dir` | str | 否 | 默认 `artifacts/<run_id>` |
| `mode` | `pipeline`/`agent`/`auto` | 否 | 默认 `pipeline`。`agent` 由模型选择分析工具（仅天气）；`auto` 有模型且天气时走 agent，否则回退 pipeline |
| `agent_max_steps` | int | 否 | Agent 最大决策步数，默认 8，仅 `mode=agent` 生效 |
| `agent_scope` | `guided`/`free` | 否 | 默认 `guided`：按问题关键词推下限，未覆盖不得结束，下限外最多追加 `agent_max_extra_steps` 步；`free` 为 T2.2 原始语义（范围完全由模型决定，步数会波动） |
| `agent_max_extra_steps` | int | 否 | 下限之外允许追加的步数，默认 1，仅 `guided` 生效 |
| `agent_max_tokens` | int | 否 | Agent 累计 token 上限，默认 0（不限制）。只约束模型调用；到限时在**下一次调用之前**拦下（前置预扣），以 `token_budget` 结束 |
| `price_table` | str/null | 否 | E2 价目表 JSON 路径，用于把 token 估算成金额；缺省读环境变量 `MTSA_PRICE_TABLE`。都未配置时**不做金额换算**（不按 0 计价）；路径无效或字段缺失直接返回 `PRICE_TABLE_INVALID` |
| `max_cost` | float/null | 否 | 金额预算上限，币种与价目表 `currency` 一致；缺省读 `MTSA_MAX_COST`。**超支只标记、不中止**（见 3.6 成本语义）；设了上限却没配价目表会直接 `PRICE_TABLE_INVALID` |
| `replay_from` | str/null | 否 | 从一次 agent 运行的 `result.json` 离线重放；设置后不调用模型，计划与步骤取自记录 |
| `forecast` | bool | 否 | 附加预测（F），默认 `false`。仅天气场景生效；关闭时不产生 `data.forecast` |
| `forecast_horizon` | int/null | 否 | 预测步数，缺省为一个季节周期；上限 168 |

### 3.1 计划层

计划由 `src/mtsa/planner.py` 产出，节点 04 调用。两种实现共用同一返回约定：

| 实现 | 触发条件 | `plan_source` |
| --- | --- | --- |
| `RulePlanner` | 未配置 LLM，或显式 `MTSA_PLANNER=rule` | `rule` |
| `LLMPlanner` | 已配置端点与密钥 | `llm`（首次）/ `cache`（命中缓存） |

LLM 计划的产出必须通过三级校验（格式、schema、语义），任何一级失败即回退规则计划，回退原因写入 `warnings`。`AnalysisPlan` 因此新增两个字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `plan_source` | str | `rule` / `llm` / `cache` / `mock`，计划来源 |
| `planner_version` | str | 提示词与校验规则版本，变更时递增，用于缓存整体失效 |

模型可调整的参数限于 `seasonal_period`、`max_lag`、`rolling_window`、`change_point_depth`；`anomaly_threshold`、`change_point_sse_ratio`、`close_column` 属于统计标定结果，禁止模型修改。

**表 3-1 计划层配置项**

| 环境变量 | 取值 | 缺省 |
| --- | --- | --- |
| `MTSA_PLANNER` | `auto` / `llm` / `rule` | `auto`：有密钥用 llm，否则 rule |
| `MTSA_LLM_BASE_URL` | OpenAI 兼容端点，如 `https://api.deepseek.com/v1` | 空 |
| `MTSA_LLM_API_KEY` | 密钥 | 空 |
| `MTSA_LLM_MODEL` | 模型名 | `deepseek-chat` |
| `MTSA_LLM_TIMEOUT` | 秒 | `30` |
| `MTSA_PLAN_CACHE` | 缓存目录 | `artifacts/plan_cache`，置空则关闭缓存 |

### 3.4 执行入口与保护

两种入口，选择取决于调用方能否接受进程开销：

| 入口 | 隔离 | 超时 | 适用 |
| --- | --- | --- | --- |
| `engine.run_analysis(req)` | 否，进程内 | 无 | 库调用、测试、被外部调度器托管 |
| `timeout_guard.run_with_timeout(req, timeout_s)` | 是，子进程 | 有，默认 600 s | CLI 默认路径、无人值守运行 |

之所以要子进程而非在主线程加计时器：**Python 无法中断正在执行的 C 扩展调用**（numpy、statsmodels、LAPACK），一旦进入就不会返回解释器。主线程的计时器只能在节点之间生效，而卡死恰恰表现为「节点不返回」。

**表 3-2 运行保护配置项**

| 环境变量 / 参数 | 含义 | 缺省 |
| --- | --- | --- |
| `MTSA_MAX_ROWS` | 规模上限（行数），超过即 `DATASET_TOO_LARGE` | `200000` |
| `--timeout SEC` | 整体超时秒数；`0` 表示不设超时且退回进程内 | `600` |

失败时引擎也会写 `result.json`（此前只有成功路径落盘）。因此调用方判断成败**必须以 `status` 为准，不能以「产物目录非空」判断**。

### 3.5 分析层工具（`mtsa.tools`）

六个分析节点被包装为可独立调用的工具，供自主循环（T2.2）编排。数据管道（导入至清洗）与收尾（图表至报告）**不在此列**：前者有严格前置依赖，后者需聚合全部结果。

| 工具名 | 底层函数 | 适用场景 |
| --- | --- | --- |
| `compute_metrics` | `metrics.compute_metrics` + `adapter.extra_metrics` | 数值大小、波动、收益风险、总体画像 |
| `analyze_spectrum` | `freq.analyze_spectrum` | 周期、季节性、振荡节律 |
| `run_stat_tests` | `stats_tests.run_stat_tests` | 需推断性结论（显著、平稳、有趋势） |
| `detect_anomalies` | `anomaly.detect_anomalies` | 异常点、离群值、故障 |
| `detect_change_points` | `anomaly.detect_change_points` | 拐点、水平跳变、行为改变 |
| `check_lookahead` | `scenarios.stock.check_lookahead` | 仅股票场景；其他场景返回 `skipped` |

**表 3-3 工具接口**

| 类型 | 字段 | 说明 |
| --- | --- | --- |
| `ToolContext` | `clean`、`plan`、`adapter` | 只读上下文，工具不得修改其中任何对象 |
| `ToolResult` | `tool`、`outcome`、`summary`、`data`、`elapsed_ms`、`error`、`reason` | 见下 |

`outcome` 三种取值：

| 值 | 含义 | 调用方应如何处理 |
| --- | --- | --- |
| `ok` | 执行成功（产出可能为空，看 `summary.result_count`） | 继续 |
| `skipped` | 前置条件不满足，未执行（如非股票场景的泄漏检查） | 不视为错误 |
| `failed` | 执行中抛异常或工具名未注册 | 由调用方决定中止或换工具 |

**`summary` 与 `data` 分离是本设计的关键约束**：`summary` 是结构化短摘要，将进入模型上下文；`data` 是完整结果，仅代码使用。`summary` 中不得出现原始数据数组——例如 `SpectrumResult` 的 `freqs`、`power` 长度等于样本量，绝不进入摘要。这一条由测试断言。

工具的三条性质同样由测试锁死：

1. **产出等价**：`data` 与直接调用底层函数的结果逐字段相等。
2. **幂等**：同一上下文重复调用同一工具，`summary` 相同。
3. **无副作用**：调用前后 `ctx.clean.frame` 与 `ctx.plan` 完全不变。

固定流水线（`pipeline` 模式）**仍直调底层函数**，不经过工具层。两条路径共享同一批底层实现，等价性由上面的第 1 条测试持续保证。这样既不为已验证的路径引入风险，也避免工具层成为无人使用的死代码——一旦底层函数改动而工具层未同步，测试会立即失败。

### 3.6 Agent 模式（仅天气）

T2.2 起，CLI 支持：

```text
--mode pipeline|agent|auto  # 默认 pipeline
--agent-max-steps N       # 默认 8
```

**范围**：本轮 Agent 只支持 `weather`。股票场景请求 `mode=agent` 直接返回 `AGENT_SCENE_UNSUPPORTED`，不静默降级到 pipeline。

**模式选择**：CLI `--mode pipeline|agent|auto`，缺省读环境变量 `MTSA_AGENT`：

| 取值 | 结果 |
| --- | --- |
| 未设置 / `off` / `false` / `0` / `pipeline` | `pipeline` |
| `agent` / `on` / `true` / `1` / `yes` | `agent` |
| `auto` | `auto` |

优先级：显式 `--mode` > `MTSA_AGENT` > `pipeline`。
`auto` 的判定：重放源存在 → agent；场景不是天气 → pipeline；无模型客户端 → pipeline；
其余 → agent。回退原因写入 `warnings`。

`result.datasets[0]` 记录实际生效值：

| 字段 | 含义 |
| --- | --- |
| `mode` | `pipeline` 或 `agent` |
| `mode_requested` | `pipeline` / `agent` / `auto` |

**天气白名单**（模型只能从这五个里选）：

```text
compute_metrics
analyze_spectrum
run_stat_tests
detect_anomalies
detect_change_points
```

`check_lookahead` 是股票专属工具，不进入天气白名单；它仍保留在工具注册表中供 pipeline 使用。

**执行边界**：

| 层 | 节点 | 是否由模型决定 |
| --- | --- | --- |
| 准备层 | 导入、规模、摘要、质量、场景、计划、清洗 | 否，固定 |
| 分析层 | 上述五个工具 | 是，模型逐步选择；`guided` 下界由问题关键词确定，上界为「下限 + `agent_max_extra_steps`」，总步数不超过 `agent_max_steps` |
| 收尾层 | 图表、报告、证据校验 | 否，固定 |

模型每步输出 `{"action", "args", "reason"}`；`args` 必须为空对象（工具参数全部来自计划），`reason` 不得为空。白名单外工具、锁定参数、未知参数、成功工具的重复调用都会被拒绝；失败工具允许重试一次。拒绝原因回灌模型，连续越界 3 次终止。规则实现在 `src/mtsa/agent_guards.py`。

**`result.json` 新增 `data.agent`**：

| 字段 | 含义 |
| --- | --- |
| `mode` | 固定为 `agent` |
| `model` | 客户端声明的模型名；Mock 运行时为 `fake-model` |
| `allowed_tools` | 本场景白名单 |
| `terminate_reason` | `model_finished` / `max_steps` / `idle_loop` / `decision_error` / `scope_unmet`（下限始终未覆盖）/ `budget_exhausted`（下限外追加步数用尽）/ `token_budget`（累计 token 到限，或在下次调用前预扣失败） |
| `step_count`、`tools_run` | 步数与成功执行的工具 |
| `steps[]` | 每步 `action`、`args`、`reason`、`outcome`、`summary`、`elapsed_ms`、`started_at` |
| `rejects[]` | 被拒动作及原因 |
| `elapsed_ms`、`max_steps` | 本次循环耗时与步数上限 |
| `budget` | token 预算：`limit`、`used`、`remaining`、`enforced`、`exhausted`、`unavailable`、`precheck`。`enforced=false` 表示未设限；`unavailable=true` 表示设了限但服务端未返回 usage，预算未生效；`precheck` 见下 |
| `budget.precheck` | 前置检查：`enabled`（是否具备检查条件）、`reserve`（下一次调用预计消耗的 token）、`basis`（`observed_max` / `observed_avg` / `unavailable`）、`blocked`（本次是否为调用前拦截）。`blocked=true` 时 `used < limit`，差额已不够一次调用 |
| `scope` | 范围下限（`guided`）：`mode`、`enforced`、`source`、`tools`、`matched`（命中的关键词）、`missing`、`met`、`extra_used`、`max_extra_steps`、`scope_rejects`；`free` 为 `{"mode": "free", "enforced": false}` |
| `coverage` | 覆盖情况：`allowed_tools`、`executed_tools`、`missing_tools`、`tool_coverage`、`planned_analyses`、`covered_analyses`、`missing_analyses`、`analysis_coverage`、`tools[]` |
| `tool_states` | 每个白名单工具的最终状态：`ok` / `skipped` / `failed` / `not_run` |
| `guard_events` | 越界事件：步序、动作、类型、说明 |
| `guard_stats` | 越界总数、按类型计数、连续越界、重试次数、策略快照 |
| `trajectory_sha256` | 决策路径的规范化哈希（不含耗时/时间戳） |
| `replay` | 重放信息：源路径、源哈希、重放哈希、轨迹/数据是否一致、差异列表 |
| `tokens` | 服务端返回的用量累计：`calls`、`prompt_tokens`、`completion_tokens`、`total_tokens`、`cached_tokens`、`max_call_tokens`（单次调用最大值，供前置预扣使用）；未返回 `usage` 时该字段缺失 |
| `cost` | E2 成本估算，**仅在配置了价目表且服务端返回 usage 时出现**：`estimated`（恒为 `true`）、`currency`、`unit_tokens`、`tokens`（`prompt`/`cached`/`completion`）、`breakdown`（`input`/`cached_input`/`output`）、`total`、`price`（价目表快照含 `path`/`source`/`effective_date`/`model`/`tier`）、`cached_price_fallback`、`model_match`（价目表声明的模型与实际调用是否一致，任一方缺失为 `null`）、`budget`（配了 `max_cost` 时出现：`limit`/`exceeded`/`over_by`/`remaining`/`policy=mark_only`）、`note`。金额不参与任何统计计算 |

失败语义：

| 情况 | `error.code` |
| --- | --- |
| 无模型配置 | `AGENT_UNAVAILABLE`（`details.required_env` 列出缺的变量） |
| 非天气场景 | `AGENT_SCENE_UNSUPPORTED`（`details.scene` 给出实际场景） |
| 模型未执行任何工具就结束 | `AGENT_NO_RESULT`（轨迹仍写入 `result.json`） |
| 单个工具失败 | 运行不中止；该工具记 `failed`，写入 `warnings` |
| 下限未覆盖就要求结束 | 不终止；记 `rejects[].kind=scope_incomplete`，把缺口回灌模型；连续 3 次记 `scope_unmet` |
| 累计 token 达上限 | 在下次模型调用前停止，`terminate_reason=token_budget`；已选中的工具仍执行完，`warnings` 说明「不能当作完整分析引用」 |
| 下一次调用会超限 | 调用**前**拦截（`budget.precheck.blocked=true`、`used<limit`），不发这次请求；`warnings` 写明已用量、上限与预计消耗 |
| 价目表路径无效 / 字段缺失 | 返回 `PRICE_TABLE_INVALID`，在构造 Agent 之前失败，不消耗 token；不静默按 0 计价 |
| 设了预算但服务端无 usage | 运行继续，`budget.unavailable=true`，`warnings` 写明预算未生效 |
| 下限外追加超预算 | 不执行；记 `rejects[].kind=scope_exceeded`（不计入 `guard_events`，因为动作本身合法），立即以 `budget_exhausted` 结束 |

**成本语义（E2）**：金额只在 `mode=agent` 且显式配置价目表时计算。

- 价目表由 `--price-table` 或 `MTSA_PRICE_TABLE` 指定，格式见 `config/prices.example.json`；
  `unit_tokens`（按 1K 还是 1M 报价）与 `source`（价格出处）必填——这两项决定金额是否可比、可复核，
  所以不给默认值；
- 未配置价目表：不产出 `cost`，报告也不出现成本行（不写 0 冒充免费）；
- 配置了价目表但服务端未返回 usage：`warnings` 写明「金额无法计算（不估算）」；
- `cached_input` 省略时缓存命中的 token 按 `input` 计价，并用 `cached_price_fallback=true` 标出；
- 金额是估算：`estimated=true`、`price.path`、`price.effective_date` 可追溯；
  它只用于展示与预算提示，不进入指标、结论或门禁；
- 预算前置检查用真实观测值预扣（`observed_max` 优先，其次 `observed_avg`）；
  `calls=0` 时无依据，第一次调用仍只能事后判断，并在 `precheck.basis=unavailable` 标出；
- **两套预算语义，不要混用**：`agent_max_tokens` 在下一次调用前硬停（防跑飞）；
  `max_cost` 跑完再对账，超支只写 `budget.exceeded=true` 与 warnings，
  `status` 仍是 `succeeded`（用金额硬停会逼出「花到多少就中断」的半份报告）；
- `max_cost` 只在 `mode=agent` 生效；pipeline 不调用模型，配置了会得到一条
  「金额预算不适用」的 warning；
- 价目表声明了 `model` 而实际调用的模型不同时，`model_match=false` 并进 warnings：
  价格挂错模型会让金额整体偏差，但按「跑完再标记」的约定不中止；
- 随包的 `prices/*.json` 是手填表（CNY / 每百万 token / 分 peak 与 offpeak 两档），
  `config/prices.example.json` 只是字段模板，里面的数字不是任何供应商的真实报价。

未执行的分析工具会写入 `warnings`，报告 `### 3.1 Agent 执行轨迹` 也会列出「未执行工具」。**未执行不等于未发现问题**，引用结论时必须带上这一限定。

**观察摘要**由 `src/mtsa/observation.py` 生成，运行时不再直接拼接历史。约束：

- 单步摘要约 400 token 以内，整步上下文目标低于 6000 token；
- 列表最多 4 项、字符串最长 80 字符，超出写「…共 N 项」；
- 不包含原始数据数组；
- 超预算时优先压缩较早步骤，其次压缩最近步骤，最后裁剪列清单。

`analysis_coverage` 以「本次计划的分析项」为分母，计划很窄时可能为 1.0；
`tool_coverage` 以五个白名单工具为分母。两者必须同时看，不能互相替代。

`coverage.tools[]` 逐工具给出 `{tool, state, reason, covers}`：`state` 与 `tool_states` 一致；`reason` 对 `failed` 是异常信息，对 `skipped` 是前置条件，对 `not_run` 区分「模型未选择 / 被范围策略拒绝 / 未轮到（终止原因）」；`covers` 是该工具负责且落在本次计划里的分析项。
评估侧另有固定分母的「规则计划覆盖率」（12 项），口径与用途见
`doc/评估设计.md` 第 6.5 节。

**Agent 评估输出**：`python -m evals.agent_eval` 写入
`evals/agent_eval_results.json`，字段为 `source`（`real`/`mock`）、`model`、
`planner`、`cases[]`、`summary`、`thresholds`。只有 `source=real` 会被
`evals/run_evals.py` 纳入判定。

**对照实验输出**：`python -m evals.mode_compare` 写入
`evals/mode_compare_results.json`，字段为 `source`、`model`、`planner`、
`n_cases`、`pipeline`（汇总）、`agent`（汇总）、`deltas`、`cases[]`
（每个用例两模式的结论/证据/覆盖率/耗时/token）、`checks`。

**安全边界（T2.4）**：`anomaly_threshold`、`change_point_sse_ratio`、`close_column`
属于已标定参数，模型修改会被拒绝；工具目前不接受任何额外入参。
越界类型写入 `guard_stats.by_kind`：`tool_not_allowed`、`locked_parameter`、
`unknown_argument`、`step_budget`、`duplicate_tool`。

**失败恢复（T2.7）**：`failed` 表示试过但失败，`skipped` 表示前置条件不满足，
`not_run` 表示模型没选。三者不能合并成「未执行」。失败工具可重试一次；
报告与 `warnings` 会分别标注。

**离线重放（T2.5）**：

```powershell
python -m mtsa.cli run --replay artifacts/<run_id>/result.json --output artifacts/<run_id>_replay
```

重放时：

- 使用记录里的 `data.plan`，不重新规划；
- 不构造模型客户端；
- 仍执行导入、摘要、质量检查与清洗，确保输入未变；
- 按记录顺序重跑工具；
- 比对 `trajectory_sha256` 与 `data`（除 `agent` 外）；
- 不一致返回 `REPLAY_MISMATCH`，并给出差异路径。

`--replay` 可省略 `--input` 与 `--question`，会自动从原结果读取。
若显式传入 `--input`，必须是同一份数据，否则会因结果不一致而失败。

### 3.7 预演（`--dry-run`）

`mtsa run --dry-run` 只走「导入 → 摘要 → 质量 → 场景 → 计划」五步就返回：

- **不创建产物目录**，不写 `result.json` / `report.md` / 图表；
- **不调用任何检测器或渲染函数**（`compute_metrics` / `analyze_spectrum` /
  `run_stat_tests` / `detect_*` / `build_figures` / `render_report` 全部未执行）；
- **计划与真跑同源**：同一 planner、同一份参数，预览说 12 项，真跑就是 12 项。

存在理由是「先确认目标再花钱」：`--question` 写偏了，几秒内就能看出来，不必等两分钟
拿到一份范围不对的报告。不接受 `--replay`（重放的是已有轨迹，没有可确认的计划）。

返回 `status=succeeded`，`data.preview`：

| 字段 | 含义 |
| --- | --- |
| `input` | 路径、格式、行数、列、时间列与起止、采样间隔、分组列与组数、数值列 |
| `quality` | 问题条数、最大缺失率、重复时间戳、乱序、采样缺口、异常候选 |
| `scene` | `scene_id`、`confidence`、`source`（显式指定 / 自动识别） |
| `mode` / `mode_requested` | 解析后的执行模式与请求模式（`auto` 在这里落实） |
| `plan` | `plan_source`、`planner_version`、`analyses`、`target_columns`、`parameters` |
| `tools` | 将要执行的工具：pipeline 为计划各项；agent 为五个白名单工具（模型选择，不保证全跑） |
| `warnings` | 计划层回退、单侧单位变化等提示 |
| `output_dir` | 真跑会写入的目录（本次未创建） |

## 4. 核心数据结构

| 模型 | 关键字段 |
| --- | --- |
| `DatasetSpec` | `path`、`format`、`time_column`、`value_columns`、`group_column`、`unit`、`sampling_interval` |
| `RawDataset` | `frame`（DataFrame）、`spec`、`file_hash`、`row_count`、`column_dtypes` |
| `DatasetProfile` | `time_axis`（列名、可解析率、起止、中位间隔、是否单调）、`numeric_columns`、`categorical_columns`、`group_columns`、`sampling`（推断频率、间隔稳定性、不连续段列表） |
| `QualityIssue` | `code`、`severity`（`error`/`warn`/`info`）、`column`、`group`（问题所属分组取值）、`row_label`（触发位置原始行标签）、`start`、`end`、`count`、`detail`、`runs`（可定位连续段 `[{start,end,count}]`，多实体段带 `group`）、`run_count`（截断前总段数）、`runs_truncated`（是否超过 20 段） |
| `QualityReport` | `issues`、`missing_ratio`、`duplicate_timestamps`、`out_of_order`、`gap_count`、`anomaly_candidate_count`、`as_of`（取数据截止时间，非墙钟时间） |
| `CleanDataset` | `frame`、`operations`（按顺序记录执行的清洗动作）、`dropped_rows`、`imputed_cells`、`imputed_index`（被插值填补的采样点，异常检测时排除）、`unit_conversions` |
| `MetricRow` | `metric_id`、`name`、`column`、`group`、`value`、`unit`、`window`、`method`、`formula` |
| `MetricTable` | `rows`、`generated_by`、`code_ref` |
| `SpectrumResult` | `column`、`sampling_rate`、`freqs`、`power`、`dominant_freq`、`dominant_period`、`band_power`、`method` |
| `TestResultRow` | `test_id`、`name`、`column`、`statistic`、`p_value`、`critical_value`、`reject_null`、`conclusion`、`assumptions` |
| `AnomalyPoint` | `index`、`timestamp`、`column`、`value`、`score`、`method` |
| `ChangePoint` | `index`、`timestamp`、`column`、`kind`（`mean`/`variance`）、`statistic`、`confidence` |
| `Artifact` | `artifact_id`、`kind`（`figure_static`/`figure_interactive`/`table_csv`/`report_md`/`script`）、`path`、`title`、`fields`（图表字段映射）、`sha1` |
| `Evidence` | `evidence_id`、`claim`、`metric_ids`、`artifact_ids`、`code_ref`、`caveat` |
| `AnalysisResult` | 公共字段 + `quality`、`profile`、`metrics`、`spectrum`、`tests`、`anomalies`、`change_points`、`extremes`、`conclusions` |

> `data.extremes`（D2；D3 修正）：每项含 `column`、`tail`（`high`/`low`）、`quantile`、`threshold`、`count`、`run_count`、`runs`、`runs_truncated`。按经验分位判定「绝对极端」，与 `anomalies` 的统计异常不是同一判据。单列单侧最多保留 **2000** 段（D3 从 100 提高：100 段在 7 年小时序列上砍掉了 3/4 的时间轴，事件覆盖会被上限而不是判定能力决定）；截断时 `runs_truncated=true` 且引擎写 warning。插补排除按**列**（`CleanDataset.imputed_columns`），不再用行级并集。

> `data.forecast`（F，仅 `forecast=true` 且天气场景时出现）：顶层含 `enabled`、`period`、`horizon`、
> `interval_level`、`methods`、`baseline`、`origins`、`calib_window`、`columns`、`disclaimer`。
> `columns[]` 每项含 `column`、`status`（`ok`/`insufficient_data`）、`points`、`period`、`horizon`、
> `origins`、`origins_used`、`methods[]`（`method`/`origins`/`n`/`mae`/`rmse`/`mase`）、`selected`、
> `selected_reason`、`selected_mase`、`baseline`、`baseline_mase`、`beats_baseline`、
> `interval_level`、`interval_method`、`interval_coverage`、`interval_coverage_points`、`forecast[]`
> （`timestamp`/`value`/`lo`/`hi`）。关闭时该键**不存在**（不是空对象）。

## 5. 错误码

| `error.code` | 触发条件 | HTTP 语义（T2 启用后） |
| --- | --- | --- |
| `DATA_LOAD_FAILED` | 文件不存在、为空或格式不支持 | 400 |
| `TIME_AXIS_NOT_FOUND` | 无法识别时间字段 | 400 |
| `EMPTY_NUMERIC_COLUMN` | 所有数值列全缺失 | 422 |
| `SCENE_NOT_DETECTED` | 场景置信度 < 0.34 且未显式指定 | 400 |
| `SAMPLING_TOO_COARSE` | 请求的分析需要更细采样 | 422 |
| `LOOKAHEAD_VIOLATION` | 回测检测到未来数据泄漏 | 422 |
| `NODE_TIMEOUT` | 整体分析超过 `--timeout` 秒（默认 600），子进程被终止 | 504 |
| `DATASET_TOO_LARGE` | 数据行数超过规模上限（默认 20 万行，可用 `MTSA_MAX_ROWS` 放宽） | 413 |
| `AGENT_UNAVAILABLE` | `mode=agent` 但缺少模型配置 | 503 |
| `AGENT_SCENE_UNSUPPORTED` | `mode=agent` 但场景不是天气（本轮） | 422 |
| `AGENT_NO_RESULT` | Agent 未成功执行任何分析工具 | 502 |
| `REPLAY_INVALID` | 重放源不可用、非 agent 结果，或重放参数非法 | 422 |
| `REPLAY_MISMATCH` | 重放轨迹或结构化数据与原运行不一致 | 409 |
| `PRICE_TABLE_INVALID` | 指定了价目表但文件不存在、JSON 非法或缺字段（`currency`/`unit_tokens`/`input`/`output`/`source`） | 422 |
| `INTERNAL_ERROR` | 未分类异常（携带 `details.trace_id`） | 500 |

失败时不返回占位结果；`data` 为空，`error.details` 给出可操作提示。

`DATASET_TOO_LARGE` 的 `details` 含 `rows`、`limit`、`measured`（各规模的实测耗时）与 `hint`（降采样或分片的建议）。该检查在导入后立即执行，不进入摘要与后续节点——否则用户要等几分钟才看到报错，体感与卡死无异。

## 6. 指标口径

| `metric_id` 前缀 | 含义 | 计算方式 |
| --- | --- | --- |
| `ts.trend.*` | 趋势 | OLS 斜率、Mann-Kendall、年化漂移 |
| `ts.vol.*` | 波动 | 标准差、年化波动、滚动波动、ATR 类极差 |
| `ts.corr.*` | 相关 | Pearson、Spearman、滞后相关（lag 范围与最优 lag） |
| `ts.extreme.*` | 极值 | 分位数阈值、超阈次数、极值持续时长 |
| `ts.spec.*` | 频域 | FFT 幅值、Welch 功率谱、主频与周期、分频段能量 |
| `stk.ret.*` | 收益（股票场景） | 简单收益、对数收益、累计收益 |
| `stk.risk.*` | 风险（股票场景） | 年化波动、最大回撤、回撤区间、夏普、索提诺 |
| `stk.bt.*` | 回测（股票场景） | walk-forward 分段、分段收益、基准对比 |

所有指标必须可由 `code_ref` 定位到具体函数，禁止文档直接给出数值。
