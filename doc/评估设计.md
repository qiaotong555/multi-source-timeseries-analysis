## 2. 指标与阈值

| 指标 | 计算方式 | 阈值 |
| --- | --- | --- |
| 数据类型识别率 | 正确识别的数值列 / 全部数值列 | = 1.00 |
| 时间字段识别率 | 正确识别时间列的数据集 / 数据集总数 | = 1.00 |
| 采样异常检出率 | 检出的注入采样问题 / 注入采样问题总数 | ≥ 0.90 |
| 方法选择准确率 | 场景与分析项选择正确数 / 用例总数 | ≥ 0.90 |
| 关键指标复算误差 | 独立脚本复算与引擎输出的相对误差 | ≤ 1e-6 |
| 异常检测 Precision / Recall | **holdout 段平均**，阈值在对应 dev 段选定，数据为 `weather_eval_v1` | 均 ≥ 0.70，且有效折数 ≥ 2 |
| 事件级异常召回率 | 检出点按「同列 + 间隔 ≤ 3 小时」合并为事件，与真值事件按时间重叠匹配 | ≥ 0.70 |
| 集体异常召回率 | 仅统计 `anomaly_type=collective` 的真值事件 | ≥ 0.70 |
| dev 与 holdout 精度退化 | 各折 (dev 精确率 − holdout 精确率) 的最大值，只惩罚正值 | ≤ 0.20（样本分辨率决定，见 3.3） |
| dev 与 holdout 召回退化 | 各折 (dev 召回率 − holdout 召回率) 的最大值，只惩罚正值 | ≤ 0.20 |
| 变化点检出率 | 5 个位置（0.25–0.85）× 8 个幅度网格注入，统计「定位误差 ≤ 3」的比例；验收取 Δ=18 hPa（实测可靠检出下限） | ≥ 0.80 |
| 变化点定位误差 90 分位 | 命中格子的绝对定位误差的 90 分位 | ≤ 3 个采样点 |
| 变化点伪报率 | Δ=0（不注入偏移）时仍报出变化点的比例 | ≤ 0.20 |
| 异常检测阈值 | 在 dev 段上按 Precision/Recall 权衡选定，不参看 holdout | 由扫描选出（第 2 轮三折均为 12.0） |
| 图表字段映射准确率 | 图表所用字段与计划一致的比例 | = 1.00 |
| 同输入重复运行一致率 | 两次运行 `result.json` 除 `run_id`/`generated_at` 外一致 | = 1.00 |
| 未来数据泄漏检出率 | `stock_leak_v1` 是否报错 | 必须报错（1.00） |
| 无证据结论数 | 报告中未绑定 `evidence` 的结论条数 | = 0 |

## 3. 评估集划分

为避免「在同一套数据上选阈值又报告指标」，异常检测指标采用 dev / holdout 划分，实现见 `evals/split_eval.py`。

### 3.1 切分规则

| 项目 | 规则 | 理由 |
| --- | --- | --- |
| 维度 | 按时间切分，禁止随机切分 | 时序数据存在自相关与季节结构，随机切分使 holdout 与 dev 在时间上交错，等于把答案泄漏给调参 |
| 粒度 | 按唯一时间点索引切分 | 多实体共享时间轴，按行号切分会把同一时刻的记录劈到两侧 |
| 折数与比例 | 三折前向滚动：dev 取前 60% / 70% / 80%，holdout 各取紧随其后的 20% | 单次切分的结果可能是运气，三折可观察阈值稳定性 |
| 标签同步 | 真值标签按同一时间边界过滤 | 标签与数据必须同口径，否则 TP/FP/FN 无意义 |

### 3.2 阈值选择规则

只在 dev 上执行，规则在看 holdout 之前固定：

1. 在精确率 ≥ 0.70 且召回 > 0 的候选中，取召回最高者；
2. 平票取阈值更大者（更保守，减少误报）；
3. 若无候选满足精确率约束，退化为 F1 最大者，同样平票取更大阈值。

扫描网格为 4.0 至 12.0 共八档。若三折都选在网格边界，说明在当前数据上「阈值越大越好」，该现象写入结论，不把边界值当作最优解。

### 3.3 判定粒度：点级与事件级

评估集含两类异常：孤立点（`point`）与持续段（`collective`，连续 8 小时）。两类必须用不同口径衡量。

| 口径 | 构造方式 | 适用 |
| --- | --- | --- |
| 点级 | 逐点比对真值与检出 | 孤立点 |
| 事件级 | 检出点按「同列 + 间隔 ≤ 3 小时」合并为事件；真值按 `event_id` 聚合；同列且时间区间有交集即命中，每个检出事件最多匹配一个真值事件 | 持续段，以及「一次故障被报成多次」的检验 |

若对持续段使用点级口径，一段 8 小时的异常会产出 8 个检出点，指标随异常持续时间线性失真；若只用事件级，孤立点的定位精度又会被掩盖。两个口径同时输出，各有用途。

事件级比对只统计**有真值的列**，与点级一致。未注入异常的列（如降雨）上的合理检出不计入假阳性，否则事件级精确率会被系统性压低。

### 3.4 判定规则

| 条件 | 处理 |
| --- | --- |
| 单折 holdout 真值 < 5 | 该折标记 `insufficient_truth`，不参与判定 |
| 有效折数 < 2 | 整体判**不可判定**，不判通过 |
| 有效真值合计 < 5 | 同上 |
| 每折 | 同时给出 Precision / Recall 的 Wilson 95% 置信下界 |

**退化量取方向，不取绝对值。** 衡量标准是 `dev − holdout`：正值表示在未见数据上退化（惩罚），负值表示 holdout 反而更好（说明未过拟合，不惩罚）。用绝对值会把「泛化更好」误判成「不稳定」。

**容差 0.20 的依据。** 容差应与 holdout 的样本分辨率匹配。改进 #1 阶段每折约 12 个真值，单样本波动即 1/12 ≈ 0.083，0.10 只容得下一条样本的差异；当前评估集每折 43 至 60 个真值，分辨率提升到约 0.02，0.20 相当于允许 10 条样本的正常波动，属于偏宽松但可接受的设定。容差不宜固定为某个「看起来严格」的常数，也不应在样本量变化后仍沿用旧值。

「不可判定」与「未通过」是两种不同状态：前者表示证据不足、结论无法作出；后者表示证据充分但结论为否。二者不可互相替代，也不允许用全量数据的结果顶替。

### 3.5 已知限制

1. 三折的 holdout 段存在重叠，不构成完全独立的重复实验。
2. 当前每折 holdout 有 43 至 60 个真值，召回率 0.833 的 Wilson 95% 下界为 0.630–0.758。点估计与下界均达标，但下界仍低于点估计约 0.2，引用时应给出区间而非单值。
3. **检测器为逐点判定。** 持续段之所以能检出，是因为段内每点幅度均超过阈值，而非算法识别出「这是一段」。对「单点不超阈、整段持续偏移」的漂移型异常仍检不出；真正支持段级检测需先降低噪声自相关或引入状态空间模型，当前未做。

## 4. 变化点灵敏度标定

变化点检测的接受判据是「分割后残差平方和降到全段的 0.7 以下」，本质上是要求跳变能解释足够比例的方差。这意味着**同样幅度的跳变，位置不同、难度不同**：跳变落在前段时两侧段长接近，能解释的方差多；落在末段时剩余样本少，更容易被拒绝。

单点验证无法反映这一点，因此改为网格扫描，实现见 `evals/changepoint_scan.py`。

| 项目 | 设定 | 目的 |
| --- | --- | --- |
| 位置 | 0.25 / 0.40 / 0.55 / 0.70 / 0.85 | 覆盖前段到末段，暴露位置敏感性 |
| 幅度 | 0 / 4 / 8 / 12 / 14 / 16 / 18 / 24（hPa） | 12–18 之间加密以定位边界；0 作为伪报基线 |
| 定位容差 | 3 个采样点 | 与「准确定位」的业务要求一致 |
| 判据 | `change_point_sse_ratio`，默认 0.7 | 参数化以便做灵敏度分析 |

注入在内存中完成（对清洗后序列做后缀偏移），不落盘。理由：注入只改一列的一个阶跃，不涉及质量问题与跨列关系，没有为新数据集维护 3.7 MB 文件的必要。

**结果解读的三个要点：**

1. **检出率随幅度单调上升，且存在清晰边界。** 当前数据上边界在 14–18 hPa 之间：12 及以下全漏，14 只有中部命中，16 达到 0.8，18 起 1.0。
2. **位置敏感性必须与检出率一起看。** 只看「18 hPa 全中」会误以为检测与位置无关；矩阵显示 14 与 16 hPa 时末段明显更难，这正是判据固定比例的直接后果。
3. **伪报率是必须的对照。** 没有 0 幅度基线，就无法区分「灵敏度高」与「噪声导致什么都报」。当前基线为 0.00。

下限（18 hPa）与残差噪声尺度成正比（该列噪声标准差 2.28，约 7.9 倍），换数据须重新标定，不能当作跨数据集常量引用。

## 5. 性能与规模基准

实现见 `evals/benchmark.py`，结果缓存在 `evals/benchmark_results.json`。

### 5.1 测量方式

| 决定 | 做法 | 理由 |
| --- | --- | --- |
| 进程隔离 | 每个规模在独立子进程运行，主进程 300 s 超时并可强制终止 | 100 万行有 OOM 风险，主进程内测量会让一次崩溃带走全部结果 |
| 计时与内存分轮 | 每档跑两次：一次纯计时，一次只读 `tracemalloc` 峰值 | 内存追踪会让执行慢数倍，与计时同轮会严重虚高耗时 |
| 范围 | 只测分析链（导入至变化点），不含图表渲染 | 图表耗时与图片数量强相关、与行数弱相关，混入会掩盖规模效应 |
| 规模 | 1e4 / 1e5 / 1e6 行，两站点、10 列 | 覆盖实际规模（1.75 万行）的 0.6 至 57 倍 |
| 缓存 | 评估主流程读缓存，不重跑 | 基准约 8 分钟，放进每轮评估会让验证不可用 |

### 5.2 实测与判读

| 规模 | 状态 | 耗时 | 峰值内存 |
| --- | --- | --- | --- |
| 1e4 | 完成 | 2.92 s | 82.7 MB |
| 1e5 | 完成 | 68.93 s | 849.0 MB |
| 1e6 | 超时（>300 s） | — | — |

行数涨 10 倍、耗时涨 23.6 倍，明显超线性。节点分解显示超线性几乎全部来自 `stat_tests`：该节点在 1e5 时占总耗时 90.4%，倍率 50×。原因是 ADF/KPSS 使用 `nlags="auto"`，最大滞后阶随样本量按 `12 × (n/100)^0.25` 增长，总代价约为 O(n^1.25) 量级。

因此判读性能结果时必须**同时看总耗时与节点占比**：只看「68.93 s 达标」会漏掉「90% 的时间花在一个节点上」这个更重要的信息。

### 5.3 阈值依据

| 指标 | 阈值 | 依据 |
| --- | --- | --- |
| 1e5 行分析耗时 | ≤ 120 s | 1e5 为实际规模的 5.7 倍，两分钟内完成是可接受上限；未按实测值反向贴合 |
| 1e5 行峰值内存 | ≤ 1024 MB | 1 GB 是单机批量分析的常见上限 |

**1e6 行不作为验收项。** 57 年小时级数据不是本课题场景，把它设为硬指标等于引入一个与课题无关的门槛。但其超时未完成的事实必须记录——它说明引擎缺少前置规模检查，会给多少算多少。

**缓存缺失时指标记 9999 而非 0。** 0 会被「≤ 上限」判为通过，等于把「没测过」当成达标。

## 6. 失败样例分类

| 失败类型 | 更新内容 |
| --- | --- |
| 需求或边界不清 | 更新 `spec/当前开发任务.md` 与验收标准 |
| 数据缺失或标注错误 | 更新数据说明、fixture 版本与真值标签 |
| 规则错误 | 更新规则说明、单元测试和实现 |
| 工具选择或参数错误 | 更新工具 schema、轨迹测试与计划生成逻辑 |
| 模型输出不稳定 | 收紧结构化约束、增加失败样例，不修改确定性规则迁就模型 |
| 状态或接口错误 | 更新状态机、契约测试、实现和接口文档 |
| 安全问题 | 先停止相关能力，更新权限规则和对抗测试 |

## 8. 运行方式

```bash
# 单元测试与回归测试（basetemp 每次独立，避免临时目录堆积被清理策略拦截）
python -m pytest tests -q --basetemp=artifacts/_pt_<时间戳>

```

## 9. 已知限制

1. 异常检测：3 折有效、阈值稳定，事件级与集体召回均达标；但每折 43–60 个真值，召回率 0.833 的 Wilson 下界为 0.630–0.758，引用时应给区间而非单值。
2. 异常检测器为逐点判定。持续段能检出是因为段内每点幅度均超阈，而非算法识别出「这是一段」；对「单点不超阈、整段持续偏移」的漂移型异常检不出。
3. 变化点：可靠检出下限为 18 hPa（该列噪声标准差的约 7.9 倍），低于此幅度的跳变会漏检；下限随噪声尺度变化，不可跨数据集套用。
4. 变化点判据为单一全局比例，不区分跳变位置与段长，导致末段难度显著上升。
5. 变化点标定只做了气压一列，温度/湿度/风速的下限未逐一测定。
6. **性能瓶颈高度集中**：`stat_tests` 在 1e5 行时占总耗时 90.4%，且随样本量超线性增长（10 倍行数对应 50 倍耗时）。整条链的规模特性几乎由该节点决定。
7. **引擎无规模保护**：1e6 行在 300 s 内未完成，既未降级也未提前拒绝。大文件场景下表现为「卡死」而非「明确报错」。
8. 性能基准为单次测量，未做重复取均值；峰值内存为 `tracemalloc` 追踪值，略低于进程实际 RSS。
9. 未来数据泄漏检查只能识别「信号与次日收益相关系数 > 0.80」的显式泄漏。
10. 只有 weather / stock 两个场景，CSI 与彩票场景未实现，迁移性结论限于这两类。
11. 三折 holdout 段存在重叠，不构成完全独立的重复实验。
