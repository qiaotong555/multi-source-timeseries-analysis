# 安装与首次运行

面向**拿到这个项目、要自己跑起来的人**。目标是 10 分钟内出一条带结论的报告。
所有命令在 PowerShell / bash 下等价，路径按自己的实际目录替换。

---

## 0. 先确认你能不能用

| 项 | 要求 | 说明 |
| --- | --- | --- |
| Python | **3.12 及以上** | 3.13.14 上跑过全量测试；3.12 由 CI 覆盖。3.11 装不上（numpy>=2.5 / scipy>=1.18 要求 >=3.12） |
| 操作系统 | Windows / Linux / macOS | 报告与数据都是纯 Python 计算 |
| 浏览器 | 可选（Chrome 或 Edge） | 只影响**静态 PNG**；没有浏览器时 HTML 图与报告照常产出，PNG 失败会写进 `warnings` |
| 内存 | 8 GB 起 | 20 万行、10 列约 2 分钟，峰值内存约 2 GB |
| 数据 | CSV，带可解析的时间列 | 编码 UTF-8 / UTF-8-BOM / GBK 均可 |

数据规模上限是 **20 万行**（超过直接报 `DATASET_TOO_LARGE`，不会跑到卡死）。
实测：10 万行 37 s、20 万行 124 s、50 万行 736 s。确需更大可设 `MTSA_MAX_ROWS` 放宽，
但要自己承担耗时。

## 1. 安装

### 1.1 pip 安装（推荐）

从 PyPI 安装（**发行名是 `mtsa-agent`，命令名是 `mtsa`**，两者不同）：

```bash
pip install mtsa-agent
```

从源码安装（先 cd 到仓库根目录）：

```bash
# 建议先建独立环境，避免污染系统 Python
python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux / macOS
source .venv/bin/activate

pip install .          # 装成命令，之后直接用 mtsa
```

开发时要改代码、改完立即生效，用可编辑安装：

```bash
pip install -e .
```

> 如果报 `Cannot import 'setuptools.build_meta'`，说明这个环境没带 setuptools（Python 3.12+
> 的 venv 默认不带），先 `pip install setuptools`。

### 1.2 不安装，直接跑源码

```bash
# Windows PowerShell
$env:PYTHONPATH="src"
python -m mtsa.cli list-scenes

# Linux / macOS
PYTHONPATH=src python -m mtsa.cli list-scenes
```

### 1.3 Docker

```bash
docker build -t mtsa:0.2.0 .
docker run --rm -v "$PWD/data:/data" -v "$PWD/out:/out" mtsa:0.2.0 \
    run --scene weather --input /data/your.csv --question "分析温度的趋势和异常" --output /out
```

镜像里装了 chromium 与中文字体：前者给 kaleido 导出 PNG 用，后者保证图里不是方块。

> **验证状态**：本机没有 Docker，**没有在本机构建过**；但 CI 的 `docker` job 每次都会实际
> 构建镜像并跑通三步：`docker build` → `list-scenes` → 容器内对真实数据跑一次分析。
> 也就是说镜像是可用的，只是没在你手上这台机器上验证过。构建需要联网装依赖，
> 如果你那边构建失败，先用 1.1 的 pip 方式跑通，再回来调镜像。

### 1.4 验证安装成功

```bash
mtsa list-scenes
# 期望输出两行：
# stock   股票时序分析
# weather 天气时序分析
```

## 2. 第一次运行（自带合成数据）

不需要准备任何数据文件：

```bash
mtsa demo
```

它会在当前目录建 `mtsa_demo/`，生成一份 2,211 行的合成天气数据并跑完整链路：

```
完成：run_id=...  模式=pipeline（未调用模型）
数据：.../mtsa_demo/input.csv（2,211 行，合成数据，seed=20260927）
报告：.../mtsa_demo/report.md
结果：.../mtsa_demo/result.json
```

打开 `report.md` 就能看到一次完整分析：数据体检、指标、异常、变化点、结论与证据链。
这份数据里故意注入了一段持续高温、一个气压台阶、一段连续缺失和 3 条重复时间戳，
报告应当把它们都指出来——如果没指出来，说明这次安装有问题。

### 换成自己的数据

```bash
mtsa run --scene weather \
  --input 你的数据.csv \
  --question "分析温度的趋势、季节性与极端事件" \
  --output out/first
```

看到这一行就算成功：

```
完成：run_id=run_20261024_xxxx  场景=weather  置信度=1.0  模式=pipeline
产物目录：...\out\first
```

## 3. 换成你自己的数据

只需要一个 CSV。最小例子：

```csv
timestamp,temperature,humidity
2024-01-01 00:00:00,1.2,88
2024-01-01 01:00:00,1.0,89
```

要求与约定：

| 项 | 说明 |
| --- | --- |
| 时间列 | 名字任意，能被 pandas 解析即可；格式混用或全空会报 `TIME_AXIS_NOT_FOUND` |
| 数值列 | 缺省自动识别；也可以用 `--value-columns temp,hum,rain` 指定 |
| 分组列 | 多站点/多标的用 `--group-column station`；清洗按组进行，判重按「组 + 时间」 |
| 采样间隔 | 缺省由数据推断；也可 `--sampling-interval 1h` 明确指定 |
| 行数 | ≤ 20 万行 |

多站点是**正式支持**的场景：一份长表（每行带站点列）直接传，不要自己先透视。

只处理 CSV 时不需要额外依赖。要读 Excel / Parquet / HDF5，装可选依赖：

```bash
pip install "mtsa-agent[io]"      # 发行名是 mtsa-agent（命令名才是 mtsa）
# 在仓库根目录装：pip install ".[io]"
```

`[io]` 装的是 `openpyxl` / `pyarrow` / `h5py`。没装时不会抛裸 `ImportError`，
而是明确告诉你缺哪个包、装哪一条命令。

## 4. 你会拿到什么

每次运行一个目录，目录名就是 `run_id`：

```
out/first/
├── result.json      # 机器可读：状态、指标、异常、变化点、结论、证据链
├── report.md        # 人读报告
├── clean_data.csv   # 清洗后的数据
├── fig_*.html       # 交互图（浏览器打开）
├── fig_*.png        # 静态图（需要浏览器）
└── reproduce.py     # 与本次完全相同的参数，直接重跑
```

判断这次到底成没成，**只看 `result.json` 的 `status`**，不要看目录是否为空——
失败也会落盘 `result.json`（带 `error.code` 与可操作的提示），这是故意的。

## 5. 三个可选开关

### 5.1 Agent 模式（模型自己决定先跑哪个工具）

```bash
export MTSA_LLM_BASE_URL=https://api.example.com/v1
export MTSA_LLM_API_KEY=sk-xxx
export MTSA_LLM_MODEL=deepseek-chat

mtsa run --mode agent --scene weather --input fixtures/weather_v1.csv \
  --question "分析温度的趋势、季节性和异常" --agent-max-tokens 8000
```

- 只有**天气**场景支持 Agent；股票场景会明确报 `AGENT_SCENE_UNSUPPORTED`。
- 模型的每一次选择、每个工具的执行状态与未执行原因都在 `result.json` 的 `data.agent`，
  报告 3.1 节有覆盖矩阵。
- `--agent-max-tokens` 到限时，**下一次调用之前**就会停下（预扣），不会先花完再报超限。

### 5.2 金额估算（可选）

```bash
mtsa run --mode agent ... --price-table config/prices.example.json
```

价目表格式见 `config/prices.example.json`。三条规则：

1. `unit_tokens`（按 1K 还是 1M 报价）与 `source`（价格出处）必须自己写清——不给默认值；
2. 不配价目表就不换算金额；配错会直接报 `PRICE_TABLE_INVALID`，**不会按 0 计价**；
3. 出来的数字是**估算**，带 `estimated=true`，不是供应商账单。

### 5.3 预测（仅天气，默认关闭）

```bash
mtsa run --scene weather --input fixtures/weather_eval_v2.csv \
  --question "分析温度的趋势" --forecast --forecast-horizon 24
```

给的是「在季节形态延续这个假设下」的点预测 + 90% 经验区间，方法全是季节朴素族，
**不能用于排班、避险或交易**。

## 6. 常见错误对照

| 报错码 | 你看到的现象 | 通常原因 / 怎么处理 |
| --- | --- | --- |
| `DATA_LOAD_FAILED` | 一上来就失败 | 文件不存在、空文件、不是 CSV、编码识别失败 |
| `TIME_AXIS_NOT_FOUND` | 读进来了但找不到时间 | 时间列格式混杂、时区混用、整列为空 |
| `EMPTY_NUMERIC_COLUMN` | 提示所有数值列全空 | 列名对上了但列里没数；检查分隔符与编码 |
| `SCENE_NOT_DETECTED` | 置信度 < 0.34 | 用 `--scene weather` 显式指定，或 `--value-columns` 点名 |
| `SAMPLING_TOO_COARSE` | 请求的分析需要更细数据 | 例如做日周期却只有日频数据 |
| `DATASET_TOO_LARGE` | 行数超限 | 降采样（如按小时聚合成日频）、分片，或设 `MTSA_MAX_ROWS` |
| `NODE_TIMEOUT` | 卡住后被杀 | 默认 600 s；`--timeout 0` 关闭子进程与超时（调试用） |
| `AGENT_UNAVAILABLE` | agent 起不来 | 三个 `MTSA_LLM_*` 环境变量没配全 |
| `AGENT_SCENE_UNSUPPORTED` | 股票 + agent | 股票只有 pipeline |
| `AGENT_NO_RESULT` | 模型没跑任何工具就结束 | 换问题或换模型；轨迹仍在 `result.json` 里可查 |
| `PRICE_TABLE_INVALID` | 配置了价目表但失败 | 文件不存在、JSON 非法、缺 `unit_tokens`/`source` |
| `INTERNAL_ERROR` | 未分类异常 | 带 `details.trace_id`，连同 `result.json` 一起反馈 |

## 7. 数据与隐私

- **pipeline 模式完全本地**：不联网、不上传数据，报告与图表只写在你指定的 `--output` 目录；
- **agent 模式**会把「你的问题 + 数据概况摘要（列名、量级、质量计数）」发给你在
  `MTSA_LLM_BASE_URL` 里配置的模型服务，**不发送原始数据行**。摘要内容见
  `src/mtsa/observation.py` 的 `build_observation()`，可自行核对；
- 价目表、图、结果都在本地，不经过第三方。

## 8. 这个工具**不**做什么

- 不做业务预测承诺，也不做因果推断；
- 不在没有数据的情况下判断「有没有异常」——工具没执行 ≠ 没问题，报告会写明；
- 不内置任何供应商价格；
- 不为让结果好看而调阈值、删数据或放宽验收。

## 9. 升级与卸载

```bash
pip install --upgrade .     # 覆盖安装
pip uninstall mtsa          # 卸载
```

升级后建议先跑一次自带数据（第 2 节），确认新版本在你的机器上仍然产出报告。
