# A3：方差突变通道停用

> 2026-11-03。**停止输出 `kind="variance"` 的变化点。**
> 不是因为它不好看，而是三条独立证据都指向同一件事：在本项目的样本量下，
> 这个统计量的抽样波动大于要检测的变化。**宁可不报，也不报不可验证的点。**

---

## 一、它原来怎么判

```python
w = max(12, len(y) // 40)                     # 窗口 219 点（小时数据约 9 天）
roll = y.rolling(w).std()                      # 滚动标准差
d = roll.diff().abs()                          # 单步跳变
if d.max() > 2.0 * roll.median():              # 超过基线的 2 倍 → 报一个方差点
```

每列最多报 1 个，位置取 `d` 的最大值。没有任何显著性检验，也没有可估性检查。

---

## 二、缺陷一：量纲错了，真变化永远够不到阈值

设标准差从 `s` 跳到 `2s`（方差 ×4）。相邻两步的滚动标准差之差 ≈ `s`，
而判据的基线是 `roll.median()` ≈ `s`。于是

```
d / base ≈ s / s = 1.0  <  2.0      → 永远不报
```

在 v2 上做纯方差注入（后半段残差 ×2、均值不变），五列**全部漏检**：

| 列 | 跳变 / 基线 | 判定 |
| --- | --- | --- |
| temperature@STA_A | 0.02 | 未命中 |
| humidity@STA_A | 0.09 | 未命中 |
| pressure@STA_A | 0.64 | 未命中 |
| wind_speed@STA_A | 0.27 | 未命中 |
| rainfall@STA_A | 5.02 | 位置偏 109 点 |

温度那一列比值只有 0.02，是因为原始序列的滚动标准差被日周期（振幅 6 °C）主导，
残差方差翻倍几乎不改变它。**判据要检的东西，恰好是它看不见的东西。**

真正能越过 2.0 的只有一种情形：单个极端事件支配整个窗口。降水列 93% 为 0，
剩下 7% 是重尾事件——所以它只会在降水上「报警」。

---

## 三、缺陷二：零膨胀重尾下，噪声比信号更显著

v2 的降水是**独立同分布**生成的（`u ~ U(0,1)`，`u<0.93` 取 0，否则
`exponential(2.2)×(u-0.92)/0.08`），没有任何季节结构、没有注入方差变化。
判据仍然报出两个点。用置换检验（对「对数标准差比」做标签置换，400 次）量它们的显著性：

窗口取通道自身的宽度（219 点），双侧各 438 点：

| 情形 | σ 比 | 置换 p |
| --- | --- | --- |
| v2 降水 STA_A（**iid 噪声**） | 13.07 | 0.122 |
| v2 降水 STA_B（**iid 噪声**） | 12.23 | **0.005** |
| v2 注入 σ×2（**真变化**） | 3.53 | 0.005 |
| v2 注入 σ×3（**真变化**） | 5.29 | 0.0025 |
| R01 降水（判据给出的点） | 2.49 | 0.339 |
| R03 降水（判据给出的点） | 4.01 | 0.010 |
| R15 降水（判据给出的点） | —（一侧窗口 σ=0） | — |

读法：**iid 噪声可以做到 12–13 倍的标准差比、p=0.005，与真实的 σ×2 变化（p=0.005）
完全同档**；σ×3 也只到 0.0025。要压住噪声就得把阈值设到 p<0.001，那也同时压掉了
3 倍方差变化的检出。**噪声与信号在这个统计量上不可分。**

原因很直接：每个窗口里只有 25–52 个非零点，样本标准差被其中最大的一个事件支配；
把两侧共 438 个值随机重分，十几倍的标准差比并不罕见。

顺带否掉了 Brown-Forsythe：v2 噪声（p=0.35）与真实 σ×3 注入（p=0.0067）同样分不开，
因为 F 检验建立在 |x−median| 的均值上，被单个极端事件支配。

---

## 四、缺陷三：换到去季节残差上也不成立

按 A1 的教训（周期项不是噪声），把统计量改成「去季节残差的相邻窗标准差比」，
并纠正定位偏移（`s[t]` 与 `s[t−w]` 的分界在 `t−w`）：

| 情形 | 检出位置 | σ 比 | 判读 |
| --- | --- | --- | --- |
| v2 temperature（**未注入**） | 7417 | 2.89 | 假点 |
| v2 humidity（**未注入**） | 1628 | 2.39 | 假点 |
| v2 pressure（**未注入**） | 2950 | 3.36 | 假点 |
| v2 wind_speed（**未注入**） | 1536 | 2.65 | 假点 |
| v2 temperature 注入 σ×2 | 4385（真值 4380） | 2.10 | 命中 |
| v2 humidity 注入 σ×2 | 1911（真值 4380） | 2.66 | 被假点盖过 |
| v2 pressure 注入 σ×2 | 2950（真值 4380） | 3.36 | 被假点盖过 |

**未注入时的噪声上限（2.4–3.4）已经高于真变化（2.1）。** 把阈值提到 4 能压住所有假点，
但也就同时压掉了 σ×2 的真变化——只剩 σ×4 以上的变化能报，而手上一份数据都没有这种
量级的变化，无法验证。

## 五、代价与影响

| 项 | 改前 | 改后 |
| --- | --- | --- |
| v2 门禁变化点 | tp 8 / fp 8 / **F1 0.6667** | tp 8 / fp 0 / **F1 1.0000** |
| 17 份真实数据的变化点 | 3 个（全部是降水方差） | **0 个** |
| `kind="variance"` | 会产出 | **不再产出**（schema 保留，兼容历史结果） |

必须说清三件事：

1. **F1 变成 1.0 不代表检测器变强了。** 它只说明 v2 那 2 个注入的水平跳变被准确找到、
   且不再有别的输出。真实数据上均值通道**仍然 0 检出**，这个边界没有变（A2 已量化）。
2. **真实数据丢掉的 3 个点，本来也是不可验证的。** 其中 R01 的置换 p=0.16，
   R03 / R15 的点在可估性上同样不成立（每窗非零点不足）。
3. **这不是「调阈值保指标」。** 只要把阈值从 2.0 提到 7.5 以上，v2 那 2 个点
   （statistic 7.44 / 5.44）就会消失、F1 同样变成 1.0——但那是为了让数字好看而收紧阈值：
   真实数据上的假点照旧，而且真变化也一起被压掉（σ×2 的真变化在哪都到不了 7.5）。
   停用的依据是「同一判据在**未注入**的数据上也会报警」，与阈值高低无关。

---

## 六、什么条件下可以恢复

需要的不是更好的阈值，而是**更多的样本或更合适的问题**：

1. **更长的窗口 / 更多样本**：σ 比的抽样误差约 `1/√(2n)`，窗口 219 点、非零点只有
   25–52 时误差高达 15–20%。要让 σ×2 的变化稳定超过噪声上限，每窗非零点需要上百个。
2. **两段模型**（零膨胀列的正当做法）：把「降水频率」和「降水强度」分开——
   前者是事件率变化，后者是条件强度变化。本项目在预测侧已经这么做
   （`prob_forecast` 的事件概率 + 条件区间），检测侧可以复用同一套口径。
3. **多年基线**：单年数据里「方差变化」与「季节内变率起伏」不可分离，这是 A2 已经量过的结论。

在上述条件满足之前，这个通道只会产出不可验证的点，所以停用。
