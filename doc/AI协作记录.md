# AI 协作记录

这份记录回答一个问题：**这个项目里哪些东西是 AI 写的，人是怎么确认它可以信的。**

只记「改了什么 / 人怎么复核 / 结论是什么」，不记模型的思考过程，也不把模型的自我陈述
当作验证。每条都能在仓库里找到对应文件、命令或产物；找不到出处的说法不进这份表。

## 一、每次改动都要过的五道关

1. **看 diff 的形状**：`git diff --stat` 里出现「整文件重写」就回退。本仓库索引是 LF，
   Windows 下 `Path.write_text` 默认写 CRLF，一次疏忽就能把 4,600 行文档变成全量改动。
2. **跑测试**：`python run_tests.py`；条目数以 `evals/test_logs/summary.json` 为准，
   不在文档里另抄一份会漂的数字。
3. **跑评估**：`python -m evals.run_evals`，22 项指标，「未通过项」必须为 0。
4. **跑真实链路**：`python scripts/demo.py` 或 `python -m mtsa run ...`，判成败只看
   `result.json` 的 `status`——失败时也会落盘留档，目录非空不代表成功。
5. **数字要能指到文件**：结论里的每个数字都必须落在 `evals/*.json` 或产物的某个字段上；
   落不到就不写，或明确标成「估算」。

## 三、分工边界

**AI 可以做，也必须自己验证的**：读代码、写实现、跑测试与评估、把实测数字落进文档、
发现文档与代码不一致、给出反例（例如「这条阈值在极地数据上异常密度高 8 倍」）。

**只有人能定的**（AI 只提供选项与代价，不代替决定）：

- 阈值与验收口径、是否放宽标准；
- 产品化与研究线的排序（本项目：C → B1 → B2 → B3，检测器质量挂起）；
- 对外承诺（课程提交范围、许可证、是否公开仓库）；
- 数据与标签的采集范围；
- 保留集用哪份数据——这一条 2026-10-25 由人拍板改为「新抓 3 份」，而不是从 17 份里抽。

## 四、AI 在本项目里出过的错（保留，不粉饰）

| 错在哪 | 后果 | 现在的防线 |
| --- | --- | --- |
| Windows 下用 `write_text` 改文档，行尾从 LF 变 CRLF | 整文件重写，三次；diff 里看不出真实改动 | 改完必看 `git diff --stat`；写文件统一 `newline=""` + LF |
| 把「pipeline 默认 12 项」写进 README | 与实际行为相反（缺省是 3 项） | 默认值、性能数字这类表述，必须实跑一次再写 |
| 把「Dockerfile 未验证」当成事实写进 README | 低估了自己的交付状态 | 事实类表述先查 CI 记录或产物，查不到就写「未核实」 |
| 一开始把保留集设计成「从 17 份里抽 3 份」 | 那 17 份全进过 80 次评估，抽出来也不是盲集 | 保留集必须满足「从未参与开发」，由人复核后改为新抓数据 |
| 把「放宽 SSE 比例能检出 1.0 单位的跳变」当成灵敏度写进测试并保留了半年 | 那个跳变只有 1.45σ，是噪声；同一套判据在 v2 上把 1.1σ 的漂移中点标成 `high confidence`，精确率 0.33 | 「灵敏度」必须有分母：任何检出率断言都要同时写出信噪比，否则测的是「能不能报出噪声」 |
| 给变化点加尺度门槛时先用父分段 MAD，把网格灵敏度打到 0（Δ=18 命中 0.00） | 差一步就把「修过检」做成「功能报废」 | 改判据必须同时跑灵敏度网格，只跑目标指标会做出「数字变好、能力消失」的改动 |
| 一条接口测试把提交时间写死成 `2026-11-02T10:00`，而保留期按「现在 − 1 天」算 | 第二天这条用例必然失败；看起来像回归，其实是日期过期（本次全量测试就是这样红的） | 涉及「现在」的断言一律用相对时间（now ± Δ），不写死日期 |
| 把「改提示词」当成「重跑一次评估就对了」 | 计划缓存的键里没有提示词，改完描述仍会命中旧计划；`evals/llm_eval.py` 恰好用 `cache_dir=None` 才没受影响，生产路径却会 | 判断「改动是否生效」要看它有没有进入某个**缓存键或指纹**，不能假设「改代码就生效」 |
| 上一轮把 v2 的 2 个降水方差点记成「没有真值标注，所以恒为 FP，天花板 0.667」 | 结论方向错了：查生成器才发现降水是 iid，根本没有方差变化，那两个点是判据自己造的 | 报「指标天花板」之前先查数据生成器：是标注缺失，还是检测器造假，结论完全相反 |
| 把「合成网格灵敏度提升」当成能力提升 | 差点把 B/C 方案做进产线：合成集上 Δ=8 命中 0.80，真实数据上 12 °C 台阶仍偏 6 个点 | 任何判据改动都要在**真实数据注入台阶**上验一遍，合成集的数字不能外推 |

## 五、这份记录怎么用

- 评审或答辩被问「这是不是 AI 写的」：直接给本文——写了什么、谁复核、怎么复核、结论在哪。
- 接手的人想知道某条结论可不可信：先看它在不在第二节的表里，再看它的复核方式是否覆盖了
  你关心的那一面（例如「结构可追溯」不等于「语义正确」）。
- 本文不替代 `doc/评估设计.md`（口径）与 `evals/评估记录.md`（逐轮数字），三者分工：
  本文记流程与责任，评估设计记算法口径，评估记录记每一轮的实际数值。
