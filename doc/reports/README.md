# 报告源稿

本目录存放项目报告的 **Markdown 内容源稿**。Word 版由源稿经三级流水线生成，不纳入版本库，以避免二进制文件随版本膨胀。

| 文件 | 对应交付物 | 覆盖范围 |
| --- | --- | --- |
| `第一阶段报告.md` | 多源时序数据量化分析与可视化Agent_第一阶段报告.docx | 分析引擎九模块、双场景适配器、总体设计与阶段自评 |
| `第二阶段报告.md` | 多源时序数据量化分析与可视化Agent_第二阶段报告.docx | 可视化与报告生成、固定样例、测试体系、评估闭环、四次补强、性能基准 |
| `运行实验记录.md` | 多源时序分析Agent_运行实验记录.docx | M1 计划层改造后的全部真实运行（R1 至 R5）：环境、流程、观测、结论、问题与后续运行约定 |

**改进报告的源稿不放在本目录**，而是 `doc/改进记录.md`。原因是它同时承担「持续追加的改进台账」这一职责，若在本目录再存一份，两次编辑必然产生分歧——这正是本目录「只存源稿、docx 按需生成」所要避免的同类问题。导出 Word 时直接从 `doc/改进记录.md` 取内容即可。

## 为什么只存源稿

Word 是一次性导出物，内容来自这些 Markdown。若只改 docx 而不改源稿，下次重新生成会覆盖回去，两边立刻不一致。因此约定：**内容以 Markdown 为准，docx 按需重新生成**。

## 如何生成 Word

流水线为三级：S1 文稿（即本目录的 md）→ S2 排版（HTML）→ S3 转换（DOCX）。

生成后需通过两道校验：

1. `html-review` 评分不低于 95 分，无阻断级问题
2. `convert_doc.py --require-page-furniture --require-toc` 校验内容零缺失、目录书签全部绑定

## 写作约束

Markdown 源稿中**不得出现裸的小于号与大于号**。转换引擎会将其误判为 HTML 标签起始，导致整段内容丢失。涉及比较时一律用文字表述，例如「超过 300 秒」「低于 0.70」「不超过 3」。

命令行一律写进**围栏代码块**（以三个反引号开头与结尾）。原因有两条：正文中的与号会被转义，且多行内容会被合并成一段。围栏代码块由排版脚本逐行原样保留，换行与缩进都不会丢。

## 与运行实验记录的关系

`运行实验记录.md` 是**活文档**：每次真实运行后按实验编号追加一节，记录目的、前置条件、命令、观测与结论。若新结论推翻旧结论，以新章节为准并在原处标注被修订，不删除历史记录。

## 与其他文档的关系

- 评估口径与判定规则见 `doc/评估设计.md`
